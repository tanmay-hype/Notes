1️⃣ OPERATING SYSTEMS 

1. What is a process vs a thread?
Process = independent execution unit with its own memory space; thread = lightweight unit within a process sharing memory. Threads are cheaper to create/switch but risk shared-state bugs.

2. What is context switching?
Saving the state of a running process/thread and loading another's state so the CPU can switch execution — necessary for multitasking, but has overhead.

3. What is a deadlock? Name its 4 necessary conditions.
Processes waiting indefinitely for each other's resources. Conditions: Mutual Exclusion, Hold and Wait, No Preemption, Circular Wait — all four must hold simultaneously.

4. How is deadlock prevented/avoided?
Prevention: break one of the 4 conditions (e.g., resource ordering). Avoidance: Banker's Algorithm, which checks if granting a resource keeps the system in a "safe state."

5. What is virtual memory?
Abstraction giving each process the illusion of large contiguous memory using disk (swap space) + RAM via paging, enabling programs larger than physical memory to run.

6. What is paging vs segmentation?
Paging = fixed-size blocks (no external fragmentation, some internal); Segmentation = variable-size logical divisions matching program structure (can cause external fragmentation).

7. What is thrashing?
Excessive page swapping causing CPU to spend more time on paging than actual execution — happens when degree of multiprogramming exceeds available memory.

8. What is a race condition?
Outcome depends on the non-deterministic timing of concurrent thread/process execution over shared data — fixed via locks/synchronization.

9. What is a mutex vs semaphore?
Mutex: binary lock, owned/released by the same thread. Semaphore: counter-based, can allow N concurrent accesses, signaled by any thread — more general-purpose.

10. What is a critical section?
Code segment accessing shared resources that must not be executed by more than one thread/process at a time to avoid race conditions.

11. What is the producer-consumer problem?
Classic synchronization problem where producers generate data into a shared buffer and consumers remove it — needs mutual exclusion + condition variables (or semaphores) to avoid overflow/underflow.

12. Difference between preemptive and non-preemptive scheduling?
Preemptive: OS can interrupt a running process (Round Robin, SRTF). Non-preemptive: process runs till completion or voluntary block (FCFS, SJF non-preemptive).

13. What is a zombie process?
A process that has completed execution but still has an entry in the process table because the parent hasn't read its exit status yet (hasn't called wait()).

14. What is an orphan process?
A child process whose parent has terminated before it — gets adopted by the init/system process (PID 1) to be reaped properly.

15. What is the difference between multiprogramming, multitasking, and multiprocessing?
Multiprogramming: multiple programs in memory, CPU switches when one waits (I/O). Multitasking: rapid switching to give illusion of parallel execution (time-sharing). Multiprocessing: multiple CPUs executing truly in parallel.

16. What is a page fault?
Occurs when a program accesses a page not currently in physical memory — OS pauses the process, loads the page from disk, then resumes.

17. What are the page replacement algorithms?
FIFO (oldest page out), LRU (least recently used out), Optimal (theoretical best — replace page used farthest in future). LRU is most commonly used practically.

18. What is the difference between logical and physical address space?
Logical address = generated by CPU during program execution (relative); physical address = actual location in RAM, mapped via MMU (Memory Management Unit).

19. What is copy-on-write (COW)?
Optimization where child and parent process share the same memory pages after fork() until either writes — only then is a private copy made, saving memory/time.

20. What is a system call?
Interface for user programs to request services from the OS kernel (e.g., file I/O, process creation) — transitions from user mode to kernel mode.

21. Difference between user mode and kernel mode?
User mode: restricted, can't directly access hardware/memory. Kernel mode: privileged, full hardware access — OS switches modes via system calls/interrupts for safety.

22. What is an inode in a filesystem?
A data structure storing metadata (permissions, size, pointers to data blocks) about a file — the filename itself is stored separately in a directory entry pointing to the inode.

23. What is the difference between a hard link and a soft (symbolic) link?
Hard link: another directory entry pointing to the same inode (file persists till all hard links deleted). Soft link: a separate file containing a path reference (breaks if original is deleted).

24. What is spooling?
Simultaneous Peripheral Operations On-Line — buffering output (e.g., for printers) so a faster device (CPU) doesn't wait on a slower device.

25. What is a monolithic kernel vs microkernel?
Monolithic: all OS services (drivers, FS, scheduling) run in kernel space — faster but less modular. Microkernel: minimal kernel, most services run in user space as separate processes — safer, more modular, slightly slower due to IPC overhead.

26. What is CPU scheduling's goal, and name common algorithms.
Maximize CPU utilization/throughput, minimize waiting/turnaround time. Algorithms: FCFS, SJF, Priority Scheduling, Round Robin, Multilevel Queue.

27. What is starvation, and how is it solved?
A process waits indefinitely because higher-priority processes keep getting scheduled. Solved via aging — gradually increasing priority of waiting processes over time.

28. What is the difference between a pipe and a socket for IPC?
Pipe: unidirectional (or named pipes bidirectional), used for related processes typically on same machine. Socket: works across processes/machines over a network, more general communication.

29. What is memory-mapped I/O?
Technique where I/O devices are mapped into the same address space as memory, so the CPU accesses device registers using ordinary memory instructions instead of special I/O instructions.

30. Why is Python's GIL relevant here, and how does it interact with OS threads?
Python's Global Interpreter Lock allows only one thread to execute Python bytecode at a time even on multi-core systems, so OS-level threads exist but true CPU parallelism requires multiprocessing (separate processes/interpreters) instead of threading for CPU-bound work.

2️⃣ PYTHON (30 Qs)

1. What is the GIL, and why does it matter for ML workloads?
Global Interpreter Lock ensures only one thread executes Python bytecode at a time. CPU-bound tasks don't benefit from multithreading (use multiprocessing instead); I/O-bound tasks (API calls, file reads) still benefit from threading since GIL releases during I/O waits.

2. Difference between a list and a tuple?
List: mutable, slightly more memory, slower iteration. Tuple: immutable, hashable (can be a dict key), faster and more memory-efficient — used for fixed collections.

3. What are Python generators, and why use them?
Functions using yield that produce values lazily, one at a time, without storing the whole sequence in memory — critical for processing large datasets/streams in ML pipelines.

4. Difference between deepcopy and copy?
copy() (shallow) copies the outer object but keeps references to nested objects. deepcopy() recursively copies all nested objects, creating a fully independent object.

5. What are Python decorators?
Functions that wrap other functions to extend/modify behavior without changing their code (e.g., @staticmethod, timing decorators, caching via @lru_cache) — heavily used in ML frameworks for logging/validation.

6. What is *args and **kwargs?
*args collects extra positional arguments into a tuple; **kwargs collects extra keyword arguments into a dict — used for flexible function signatures (common in model wrapper functions).

7. What is the difference between is and ==?
is checks object identity (same memory location); == checks value equality. Two equal-value lists are == but not is unless they're literally the same object.

8. What are Python's mutable default argument pitfalls?
Default arguments (like def f(x=[])) are evaluated once at function definition, so mutable defaults persist across calls, causing unexpected accumulation — fix by using None and initializing inside the function.

9. What is a list comprehension, and why prefer it over loops?
Concise syntax to build lists ([x**2 for x in range(10)]) — generally faster than explicit loops due to internal C-level optimization, and more readable for simple transformations.

10. Difference between @staticmethod, @classmethod, and instance methods?
Instance method: takes self, operates on object state. Classmethod: takes cls, operates on class-level state. Staticmethod: takes neither, behaves like a plain function grouped inside the class.

11. What is duck typing in Python?
"If it walks like a duck and quacks like a duck..." — Python doesn't check an object's type explicitly, only whether it supports the required methods/behavior, enabling flexible interfaces (relevant when passing custom objects into sklearn/PyTorch APIs).

12. What is the difference between __init__ and __new__?
__new__ creates and returns a new instance (allocation); __init__ initializes the already-created instance (setting attributes) — __new__ is rarely overridden except in metaclasses/immutable types.

13. What is exception handling in Python, and what's the difference between except Exception and bare except?
try/except/else/finally blocks handle errors gracefully. except Exception catches all standard exceptions but not system-exiting ones like KeyboardInterrupt; bare except catches literally everything, including those — generally discouraged as it can hide bugs.

14. What are Python context managers (with statement)?
Objects implementing __enter__/__exit__ (or using @contextmanager) that ensure setup/teardown (e.g., closing files, releasing GPU memory, DB connections) happens automatically even if an exception occurs.

15. What is the difference between multiprocessing and threading in Python?
threading: shares memory, limited by GIL for CPU-bound tasks. multiprocessing: separate memory/interpreter per process, achieves true parallelism for CPU-bound work (like data preprocessing) at the cost of IPC overhead.

16. What is numpy broadcasting?
Mechanism allowing NumPy to perform element-wise operations on arrays of different shapes by implicitly expanding the smaller array's dimensions without copying data — essential for efficient vectorized ML code.

17. Why is vectorization preferred over explicit Python loops in ML code?
NumPy/Pandas vectorized operations run in compiled C code, avoiding Python's interpreter overhead per-element — often 10-100x faster than manual loops for numerical computation.

18. What is the difference between shallow and deep learning framework tensors vs NumPy arrays?
Framework tensors (PyTorch/TensorFlow) support GPU acceleration and automatic differentiation (autograd) for gradient computation, while NumPy arrays are CPU-only and have no built-in gradient tracking.

19. What is memoization, and how is functools.lru_cache used?
Caching function outputs for given inputs to avoid recomputation. @lru_cache(maxsize=None) decorator automatically caches return values based on arguments — useful for expensive repeated computations (e.g., tokenization lookups).

20. What is the difference between == overloading via __eq__ and default object comparison?
By default, objects compare by identity; overriding __eq__ lets you define custom value-based equality (important when comparing custom data objects/records in a pipeline).

21. What are Python's data classes (@dataclass)?
Decorator that auto-generates boilerplate (__init__, __repr__, __eq__) for classes primarily used to store data — commonly used for structured config objects in ML pipelines.

22. What is the difference between Pool.map and Pool.apply_async in multiprocessing?
map blocks and returns results in order, good for simple parallel mapping. apply_async is non-blocking and allows callbacks, giving more flexibility for asynchronous task submission.

23. What is a Python virtual environment, and why is it important in ML projects?
Isolated Python environment with its own dependencies/versions, preventing conflicts between projects (e.g., different PyTorch/CUDA versions) — created via venv or conda.

24. What is the difference between pickle and joblib for model serialization?
Both serialize Python objects to disk. joblib is optimized for objects with large NumPy arrays (common in sklearn models), offering better performance for large numerical data than plain pickle.

25. What is monkey patching?
Dynamically modifying/extending a class or module at runtime — useful for testing/mocking but risky in production as it can create hard-to-debug side effects.

26. What is the difference between __str__ and __repr__?
__str__ gives a readable, user-facing string representation; __repr__ gives an unambiguous, developer-facing representation (ideally one that could recreate the object) — used by default when __str__ is absent.

27. What is asyncio, and when would you use it over threading for ML-serving APIs?
Single-threaded cooperative concurrency using async/await for I/O-bound tasks (e.g., handling many concurrent API requests to a model server) — more efficient than threads for high-concurrency I/O without the overhead of context switching.

28. What is the difference between .loc and .iloc in Pandas?
.loc selects by label/index name; .iloc selects by integer position — critical distinction when slicing/filtering datasets to avoid off-by-one or mislabeled selection bugs.

29. How does Python handle memory management/garbage collection?
Uses reference counting (deallocates objects when ref count hits 0) plus a cyclic garbage collector to handle reference cycles that reference counting alone can't clean up.

30. What is type hinting in Python, and why is it useful in production ML code?
Optional static type annotations (def predict(x: np.ndarray) -> float:) that don't affect runtime but improve readability, enable static analysis tools (mypy), and reduce bugs in large collaborative codebases.

3️⃣ DSA (30 Qs)

1. What is the time complexity of binary search, and its precondition?
O(log n) — requires the array to be sorted; repeatedly halves the search space.

2. Explain Big-O vs Big-Θ vs Big-Ω notation.
Big-O: upper bound (worst case). Big-Ω: lower bound (best case). Big-Θ: tight bound (average/exact growth rate) — Big-O is most commonly used in interviews for worst-case analysis.

3. What is the difference between a stack and a queue?
Stack: LIFO (Last In First Out) — used in recursion, undo operations. Queue: FIFO (First In First Out) — used in task scheduling, BFS traversal.

4. What is a hash table, and what causes collisions?
Data structure mapping keys to values via a hash function for O(1) average access. Collisions occur when two keys hash to the same index — resolved via chaining (linked lists) or open addressing (probing).

5. Explain the difference between BFS and DFS.
BFS: explores level by level using a queue — finds shortest path in unweighted graphs. DFS: explores as deep as possible using a stack/recursion — useful for topological sort, cycle detection.

6. What is the time complexity of quicksort (best, average, worst)?
Best/Average: O(n log n). Worst: O(n²) (occurs with poor pivot choice, e.g., already sorted array with first-element pivot) — mitigated using randomized pivot selection.

7. What is a balanced binary search tree, and why is it needed?
A BST where height is kept O(log n) (e.g., AVL, Red-Black Tree) — prevents degeneration into a linked list (O(n) operations), maintaining O(log n) search/insert/delete.

8. What is dynamic programming, and what are its two core properties?
Optimization technique breaking problems into overlapping subproblems, storing results to avoid recomputation. Requires: optimal substructure and overlapping subproblems.

9. Difference between memoization and tabulation in DP?
Memoization: top-down, recursive with caching (lazy). Tabulation: bottom-up, iterative filling of a table (eager) — tabulation often avoids recursion stack overhead/overflow.

10. What is a greedy algorithm, and when does it fail?
Makes locally optimal choices at each step hoping for a global optimum. Fails when local optima don't lead to global optimum (e.g., 0/1 Knapsack) — works well for problems like Activity Selection, Huffman Coding.

11. What is the time complexity of heap insertion and extraction?
Both O(log n) — heap maintains structure via "bubble up" (insert) and "bubble down" (extract-min/max), using an array-based complete binary tree.

12. What is a trie, and where is it used?
Tree-like structure storing strings character by character for efficient prefix search — used in autocomplete, spell-checkers, and IP routing tables.

13. Explain the difference between adjacency matrix and adjacency list for graph representation.
Matrix: O(V²) space, O(1) edge lookup — good for dense graphs. List: O(V+E) space, O(V) edge lookup — better for sparse graphs (most real-world graphs).

14. What is topological sorting, and where is it used?
Linear ordering of vertices in a DAG such that for every edge u→v, u comes before v — used in task scheduling, build systems, dependency resolution.

15. What is the two-pointer technique, and give an example use case.
Using two indices moving through data (often from opposite ends or at different speeds) to reduce time complexity — e.g., finding a pair in a sorted array summing to a target in O(n) instead of O(n²).

16. What is the sliding window technique?
Maintaining a subset ("window") of elements and adjusting its boundaries incrementally rather than recomputing from scratch — used for problems like "max sum subarray of size k" in O(n).

17. What is the time and space complexity of merge sort?
Time: O(n log n) in all cases (stable). Space: O(n) extra space needed for merging — unlike quicksort which sorts in-place.

18. What is a min-heap vs max-heap, and how is it used for priority queues?
Min-heap: parent ≤ children (root = smallest). Max-heap: parent ≥ children (root = largest). Priority queues use heaps to always efficiently retrieve the highest/lowest priority item in O(log n).

19. What is the difference between a singly linked list and a doubly linked list?
Singly: each node points to the next only, O(n) to traverse backward. Doubly: nodes point both forward and backward, enabling O(1) backward traversal at the cost of extra memory per node.

20. What is the knapsack problem, and what distinguishes 0/1 from fractional knapsack?
Optimization problem maximizing value within a weight limit. 0/1: items can't be split, solved via DP. Fractional: items can be split, solved greedily by value/weight ratio.

21. What is memoized recursion's risk with large inputs, and how is it mitigated?
Deep recursion can hit Python's recursion limit / cause stack overflow — mitigated by converting to iterative tabulation or increasing recursion limit cautiously (sys.setrecursionlimit).

22. What is the time complexity of searching in a hash map vs a balanced BST?
Hash map: O(1) average, O(n) worst case (collisions). BST: O(log n) guaranteed (if balanced) — hash maps are faster on average but BSTs guarantee ordered traversal and consistent worst-case bounds.

23. What is Dijkstra's algorithm used for, and its complexity?
Finds shortest path from a single source in a weighted graph with non-negative edges. Complexity: O((V+E) log V) using a min-heap/priority queue.

24. What is the difference between Dijkstra's and Bellman-Ford algorithms?
Dijkstra: faster (O(E log V)) but fails with negative edge weights. Bellman-Ford: slower (O(VE)) but handles negative weights and detects negative cycles.

25. What is a segment tree, and when is it used?
Tree structure allowing range queries (sum, min, max) and point/range updates in O(log n) — used in problems requiring frequent range queries over changing data (e.g., real-time analytics on data streams).

26. What is the difference between recursion and iteration, and their trade-offs?
Recursion: cleaner code for naturally recursive problems (trees, divide-and-conquer) but uses call-stack memory (O(depth) space) and risks stack overflow. Iteration: usually more memory-efficient, but can be less readable for complex recursive logic.

27. What is the master theorem used for?
Provides a way to determine the time complexity of divide-and-conquer recursive algorithms (like T(n) = aT(n/b) + f(n)) without manually expanding the recurrence.

28. What is amortized time complexity? Give an example.
Average time per operation over a sequence of operations, even if individual operations vary. Example: dynamic array (Python list) append() is O(1) amortized despite occasional O(n) resizing.

29. What is the difference between a complete binary tree and a full binary tree?
Complete: all levels filled except possibly the last, filled left to right (basis for array-based heaps). Full: every node has either 0 or 2 children (no node has exactly 1 child).

30. Why does DSA matter specifically for an ML/AI role (not just SDE roles)?
Efficient data structures matter for building preprocessing pipelines (tries for tokenization, heaps for beam search in NLP decoding, graphs for dependency parsing/knowledge graphs), and algorithmic thinking directly transfers to optimizing model inference/serving code.

4️⃣ SYSTEM ARCHITECTURE (30 Qs)

1. What is the difference between monolithic and microservices architecture?
Monolithic: single deployable unit with tightly coupled components — simpler to build/deploy initially but harder to scale/maintain as it grows. Microservices: independently deployable services communicating over APIs — better scalability/team autonomy but adds network/operational complexity.

2. What is a client-server architecture, and how does it apply to ML model serving?
Clients (apps/users) send requests to a server that processes and returns responses. In ML, the client sends input data via API, the server hosts the model and returns predictions — decouples model logic from consuming applications.

3. What is the difference between synchronous and asynchronous communication between services?
Synchronous: caller waits for a response (blocking) — simple but can bottleneck under load. Asynchronous: caller continues without waiting, response handled via callbacks/queues/events — better for long-running tasks like batch inference.

4. What is an API gateway, and why is it used in ML systems?
A single entry point that routes requests to appropriate backend services, handling cross-cutting concerns like authentication, rate limiting, and request routing — useful when multiple models/services are exposed to clients.

5. What is the difference between REST and gRPC?
REST: HTTP-based, uses JSON, human-readable, widely compatible. gRPC: uses HTTP/2 and Protocol Buffers (binary), faster and more efficient for internal service-to-service communication — often preferred for low-latency model-serving pipelines.

6. What is a message queue, and why is it used in ML pipelines?
A middleware (e.g., Kafka, RabbitMQ, SQS) that decouples producers and consumers of data/tasks — used to buffer incoming requests for batch inference, or to stream data for asynchronous processing without overwhelming downstream services.

7. What is the difference between a stateless and a stateful service?
Stateless: no memory of previous requests, each request is self-contained (easier to scale horizontally). Stateful: maintains session/context across requests (e.g., a conversational AI service tracking chat history) — harder to scale, often needs sticky sessions or external state stores.

8. What is an event-driven architecture?
System components communicate by producing/consuming events asynchronously (e.g., "new data arrived" triggers a retraining pipeline) rather than direct calls — improves decoupling and scalability.

9. What is the difference between a monolithic ML pipeline and a modular ML pipeline (e.g., using Airflow/Kubeflow)?
Monolithic: single script handling ingestion, training, evaluation, deployment — hard to debug/reuse. Modular: separate stages as independent, reusable components orchestrated by a DAG — enables retries, monitoring, and parallelism per stage.

10. What is a service mesh (e.g., Istio), and why might it matter for ML microservices?
Infrastructure layer managing service-to-service communication (retries, load balancing, observability, security) without changing application code — useful when many microservices (feature store, model server, preprocessing service) need consistent traffic management.

11. What is the CAP theorem?
A distributed system can guarantee at most 2 of 3: Consistency, Availability, Partition tolerance — since network partitions are unavoidable in distributed systems, the real trade-off is usually between Consistency and Availability.

12. What is horizontal vs vertical scaling in system architecture?
Vertical: adding more resources (CPU/RAM) to a single machine — simpler but has hardware limits. Horizontal: adding more machines/instances — more scalable and fault-tolerant, standard approach for serving ML models at scale.

13. What is a reverse proxy, and how does it relate to model serving?
A server that sits in front of backend services, forwarding client requests to them (e.g., Nginx) — commonly used in front of model-serving containers for load balancing, SSL termination, and request routing.

14. What is the difference between batch processing and stream processing?
Batch: processes large chunks of data at scheduled intervals (e.g., nightly retraining). Stream: processes data continuously as it arrives (e.g., real-time fraud detection) — different architectural and latency trade-offs.

15. What is idempotency, and why does it matter in ML APIs?
An idempotent operation produces the same result no matter how many times it's called (e.g., retrying a failed inference request shouldn't cause duplicate side effects) — critical for reliable retries in distributed systems.

16. What is the difference between tight coupling and loose coupling?
Tight coupling: components heavily depend on each other's internals, hard to change independently. Loose coupling: components interact through well-defined interfaces/contracts, making systems easier to evolve, test, and scale independently.

17. What is a feature store in ML system architecture?
A centralized repository storing precomputed features for both training and inference, ensuring consistency (avoiding train-serve skew) and enabling feature reuse across models.

18. What is the difference between online and offline inference architectures?
Online: real-time, low-latency predictions per request (e.g., recommendation on page load). Offline (batch): predictions computed in bulk ahead of time and stored/retrieved later (e.g., nightly scoring of all users) — chosen based on latency requirements and cost.

19. What is a circuit breaker pattern, and why is it useful for ML services?
Prevents a system from repeatedly calling a failing downstream service (e.g., an overloaded model server) by "tripping" after failures and failing fast temporarily, allowing recovery — avoids cascading failures.

20. What is a sidecar pattern in microservices?
An auxiliary container/process deployed alongside the main service to handle cross-cutting concerns (logging, monitoring, proxying) — common in Kubernetes deployments for ML model containers.

21. What is the difference between vertical and horizontal data pipelines in ML systems?
Not a standard formal term, but generally: vertical refers to end-to-end pipeline for one model/use case; horizontal refers to shared infrastructure (feature stores, common preprocessing) reused across multiple models/teams.

22. What is a load balancer's role in a multi-instance model deployment?
Distributes incoming inference requests across multiple model server replicas to prevent any single instance from being overwhelmed, improving throughput and availability.

23. What is the difference between a data lake and a data warehouse?
Data lake: stores raw, unstructured/structured data at scale (schema-on-read) — flexible for ML experimentation. Data warehouse: stores structured, cleaned data optimized for querying/reporting (schema-on-write) — used for BI and curated feature extraction.

24. What is model versioning, and why is it architecturally important?
Tracking different trained versions of a model (with metadata like training data, hyperparameters) to enable rollback, A/B testing, and reproducibility in production systems.

25. What is a blue-green deployment, and how does it apply to ML model rollout?
Two identical environments (blue=current, green=new) run in parallel; traffic is switched to the new version once validated, enabling zero-downtime deployment and instant rollback if the new model underperforms.

26. What is canary deployment?
Gradually rolling out a new model/version to a small percentage of traffic first, monitoring performance, then progressively increasing rollout — reduces risk of a bad model impacting all users at once.

27. What is the role of containerization (Docker) in ML system architecture?
Packages a model with its dependencies/environment into a portable, reproducible unit, ensuring consistent behavior across development, testing, and production — solves "works on my machine" issues.

28. What is Kubernetes' role in scaling ML services?
Container orchestration platform that automates deployment, scaling (via autoscalers), and management of containerized model-serving instances based on load/resource metrics.

29. What is the difference between latency and throughput in system design?
Latency: time taken for a single request to be processed (response time). Throughput: number of requests a system can handle per unit time — optimizing one can sometimes trade off against the other (e.g., batching improves throughput but can increase per-request latency).

30. What is observability, and what are its three pillars?
The ability to understand a system's internal state from its outputs. Three pillars: Logs (discrete events), Metrics (aggregated numeric data over time), Traces (request flow across services) — essential for debugging distributed ML systems in production.

5️⃣ DATABASE (30 Qs)

1. What is the difference between SQL and NoSQL databases?
SQL: structured, relational, fixed schema, ACID-compliant (e.g., PostgreSQL, MySQL). NoSQL: flexible schema, better horizontal scalability, often eventual consistency (e.g., MongoDB, Cassandra) — chosen based on data structure and scale needs.

2. What are ACID properties?
Atomicity (all-or-nothing transactions), Consistency (valid state transitions), Isolation (concurrent transactions don't interfere), Durability (committed data survives failures) — guarantees reliable transactions.

3. What is normalization, and name the first three normal forms.
Organizing data to reduce redundancy. 1NF: atomic column values. 2NF: no partial dependency on composite keys. 3NF: no transitive dependency (non-key columns depend only on the key).

4. When would you denormalize a database, and why?
When read performance matters more than storage efficiency (e.g., analytics/reporting, or ML feature tables) — trades some redundancy for faster query performance by reducing joins.

5. What is an index, and how does it improve query performance?
A data structure (often B-Tree or Hash) that allows the database to locate rows without scanning the entire table — speeds up reads significantly but adds overhead on writes/inserts.

6. What is the difference between clustered and non-clustered indexes?
Clustered: determines the physical order of data on disk (one per table). Non-clustered: separate structure with pointers to actual rows (multiple allowed per table) — clustered is generally faster for range queries.

7. What is a JOIN, and name the main types.
Combines rows from multiple tables based on a related column. Types: INNER (matching rows only), LEFT/RIGHT OUTER (all rows from one side + matches), FULL OUTER (all rows from both sides), SELF JOIN (table joined with itself).

8. What is the difference between WHERE and HAVING?
WHERE filters rows before grouping/aggregation; HAVING filters groups after aggregation (e.g., HAVING COUNT(*) > 5).

9. What is a transaction, and what does "rollback" mean?
A sequence of operations executed as a single logical unit. Rollback reverts all changes made in the transaction if any part fails, preserving database consistency.

10. What is database sharding?
Splitting a large database horizontally across multiple servers/nodes based on a shard key (e.g., user ID range) — improves scalability for very large datasets by distributing load.

11. What is replication in databases, and why is it used?
Copying data across multiple database servers (master-slave or multi-master) — improves read scalability, availability, and fault tolerance in case of node failure.

12. What is the difference between optimistic and pessimistic locking?
Pessimistic: locks a resource before use, blocking others until released — safer but can hurt concurrency. Optimistic: allows concurrent access, checks for conflicts at commit time (e.g., via version numbers) — better performance when conflicts are rare.

13. What is a foreign key, and what does referential integrity mean?
A column referencing the primary key of another table. Referential integrity ensures relationships stay valid — you can't insert a foreign key value that doesn't exist in the referenced table.

14. What is the N+1 query problem, and how is it avoided?
Occurs when fetching a list of records and then making a separate query per record for related data (e.g., 1 query for users + N queries for each user's orders) — avoided using JOINs or eager loading/batch fetching.

15. What is the difference between OLTP and OLAP databases?
OLTP (Online Transaction Processing): optimized for many small read/write transactions (e.g., app databases). OLAP (Online Analytical Processing): optimized for complex analytical queries over large datasets (e.g., data warehouses) — different indexing/storage strategies.

16. What is a vector database, and why is it relevant for AI/ML systems?
A database optimized to store and query high-dimensional embedding vectors using similarity search (e.g., cosine similarity, ANN algorithms) — core infrastructure for semantic search and RAG systems (e.g., Pinecone, Weaviate, FAISS).

17. What is ANN (Approximate Nearest Neighbor) search, and why not use exact search for embeddings?
ANN trades a small amount of accuracy for massive speed gains when finding similar vectors in large datasets — exact nearest neighbor search (brute-force) becomes computationally infeasible at scale (millions+ vectors).

18. What is connection pooling, and why is it important for ML applications hitting a database frequently?
Reusing a pool of open database connections instead of opening/closing one per request — reduces connection overhead, critical for high-throughput services like feature-serving APIs.

19. What is a composite index, and when should it be used?
An index on multiple columns together — useful when queries frequently filter/sort by a combination of columns; column order in the index matters for which queries it can optimize.

20. What is database partitioning, and how does it differ from sharding?
Partitioning splits a table into parts (often within the same server, e.g., by date range) for manageability/performance. Sharding specifically distributes data across multiple separate servers for horizontal scaling — partitioning can happen with or without sharding.

21. What is a materialized view?
A precomputed, stored result of a query (unlike a regular view, which is virtual/recomputed each time) — improves performance for expensive aggregations at the cost of needing periodic refresh.

22. What is the difference between a primary key and a unique key?
Primary key: uniquely identifies rows, cannot be NULL, only one per table. Unique key: also enforces uniqueness but can allow one NULL value (per most DBs), and a table can have multiple unique keys.

23. What is database isolation level, and name the common levels.
Controls how much transactions are isolated from each other's uncommitted changes. Levels (weakest to strongest): Read Uncommitted, Read Committed, Repeatable Read, Serializable — trade-off between consistency and concurrency performance.

24. What is a dirty read, non-repeatable read, and phantom read?
Dirty read: reading uncommitted data from another transaction. Non-repeatable read: re-reading a row gives different data because another transaction modified it. Phantom read: re-running a query returns different rows because another transaction inserted/deleted matching rows.

25. What is the difference between a data warehouse and a feature store (ML-specific)?
Data warehouse stores general business/analytical data optimized for BI queries; a feature store specifically stores ML features with versioning and low-latency serving for both training (batch) and real-time inference use cases.

26. What is query caching, and how does it help database performance?
Storing results of expensive/frequent queries in memory so repeated identical queries return instantly without hitting the database again — must be invalidated carefully when underlying data changes.

27. What is a stored procedure, and what's a downside of relying heavily on them?
Precompiled SQL logic stored in the database, callable as a unit — improves performance/reuse but couples business logic to the database layer, making it harder to version-control/test alongside application code.

28. What is database migration, and why does it matter in ML systems with evolving schemas?
Managed, versioned changes to database schema over time (e.g., using tools like Alembic/Flyway) — important as feature tables or metadata schemas evolve without breaking existing pipelines.

29. What is eventual consistency, and where might it be acceptable in an ML system?
A consistency model where updates propagate to all nodes eventually, not instantly — acceptable for things like analytics dashboards or non-critical logging, where slightly stale data is tolerable in exchange for higher availability/scalability.

30. How would you optimize a slow query that joins a large "features" table with a "predictions" table?
Check execution plan (EXPLAIN), ensure proper indexes on join/filter columns, consider denormalizing frequently joined data, partition large tables by time/key, and evaluate if a smaller pre-aggregated or materialized view could replace the live join.

6️⃣ COMPUTER NETWORKS (30 Qs)

1. What is the OSI model, and name its 7 layers.
A conceptual framework for network communication: Physical, Data Link, Network, Transport, Session, Presentation, Application (bottom to top) — used to standardize and troubleshoot network functions.

2. What is the difference between TCP and UDP?
TCP: connection-oriented, reliable (retransmits lost packets), ordered delivery — used for APIs, file transfer. UDP: connectionless, faster, no delivery guarantee — used for streaming, real-time inference over video/audio.

3. What is the TCP three-way handshake?
SYN (client requests connection) → SYN-ACK (server acknowledges) → ACK (client confirms) — establishes a reliable connection before data exchange begins.

4. What is HTTP vs HTTPS?
HTTP: unencrypted application-layer protocol for data transfer. HTTPS: HTTP over TLS/SSL, encrypting data in transit — essential for securing API calls to/from ML services handling sensitive data.

5. What is DNS, and how does it work?
Domain Name System translates human-readable domain names into IP addresses via a hierarchical lookup (root → TLD → authoritative servers) — critical infrastructure for locating any networked service.

6. What is the difference between a forward proxy and a reverse proxy?
Forward proxy: sits in front of clients, hiding client identity from servers (e.g., corporate proxy). Reverse proxy: sits in front of servers, hiding server details from clients and handling load balancing/SSL termination (e.g., Nginx in front of model servers).

7. What is a REST API, and what makes it "RESTful"?
An architectural style using stateless HTTP requests with standard verbs (GET, POST, PUT, DELETE) operating on resources identified by URLs — statelessness and resource-based design are key RESTful principles.

8. What is the difference between HTTP/1.1 and HTTP/2?
HTTP/1.1: one request per connection at a time (with some pipelining issues). HTTP/2: supports multiplexing (multiple requests/responses over a single connection), header compression, and is generally faster — used by gRPC.

9. What is a WebSocket, and when would you use it over REST for ML applications?
A persistent, full-duplex connection between client and server allowing real-time bidirectional communication — used for streaming model outputs token-by-token (e.g., LLM chat responses) rather than repeated REST polling.

10. What is the difference between IPv4 and IPv6?
IPv4: 32-bit addresses (~4.3 billion, largely exhausted). IPv6: 128-bit addresses (vastly larger space) with built-in security/routing improvements — increasingly necessary as connected devices grow.

11. What is a firewall, and how does it help secure ML APIs?
A system that monitors/filters incoming and outgoing network traffic based on security rules — protects model-serving endpoints from unauthorized access or malicious traffic.

12. What is latency vs bandwidth?
Latency: time delay for data to travel from source to destination (ms). Bandwidth: maximum data transfer rate of a connection (Mbps/Gbps) — high bandwidth doesn't guarantee low latency, both matter for real-time inference APIs.

13. What is a CDN (Content Delivery Network), and how might it relate to ML model serving?
A distributed network of servers caching content closer to users geographically — can be used to cache static assets or even lightweight model outputs, reducing latency for globally distributed users.

14. What is NAT (Network Address Translation)?
Technique that maps private internal IP addresses to a public IP for internet communication, allowing multiple devices to share one public IP — common in cloud VPC setups hosting ML services.

15. What is the difference between a router and a switch?
Switch: connects devices within the same LAN using MAC addresses. Router: connects different networks, directing traffic based on IP addresses — routers typically sit at the edge connecting to the internet.

16. What is load balancing at the network layer (L4) vs application layer (L7)?
L4: routes traffic based on IP/port without inspecting content (faster, less flexible). L7: routes based on actual request content (e.g., URL path, headers) — enables smarter routing like directing /predict requests to specific model servers.

17. What is an SSL/TLS handshake, and why does it matter for secure model APIs?
Process where client and server establish an encrypted connection (exchanging certificates, negotiating keys) — ensures data (including potentially sensitive input/output) is encrypted in transit.

18. What is API rate limiting, and why is it important for ML inference endpoints?
Restricting the number of requests a client can make in a given time window — protects model servers from being overwhelmed and ensures fair usage across clients.

19. What is the difference between a public and private cloud network, and why does it matter for deploying models?
Public cloud: shared infrastructure managed by a provider (AWS/GCP/Azure), easier to scale. Private cloud: dedicated infrastructure, often required for strict data compliance/security needs (e.g., sensitive ML training data).

20. What is packet switching vs circuit switching?
Circuit switching: dedicated communication path for the entire session (older telephone networks). Packet switching: data broken into packets routed independently and reassembled at destination — the basis of the modern internet, more efficient for bursty data like API traffic.

21. What is an API gateway's role from a networking perspective?
Acts as a reverse proxy that also handles authentication, rate limiting, request transformation, and routing to multiple backend microservices/model endpoints from a single entry point.

22. What is the difference between synchronous REST calls and message-queue-based communication over a network?
REST: direct request-response over HTTP, caller waits. Message queue: caller publishes a message and moves on; a consumer processes it asynchronously — better for decoupling and handling traffic spikes in ML request pipelines.

23. What is a VPN, and why might it be used when accessing ML infrastructure?
Virtual Private Network creates an encrypted tunnel over a public network, allowing secure remote access to private resources (e.g., accessing internal model training clusters securely from outside the corporate network).

24. What is DDoS, and how might it affect a publicly exposed model API?
Distributed Denial of Service — overwhelming a service with traffic from multiple sources to make it unavailable — mitigated via rate limiting, CDNs, and traffic filtering at the network edge.

25. What is the difference between a subnet and a VPC?
VPC (Virtual Private Cloud): an isolated virtual network within a cloud provider. Subnet: a smaller segmented range of IP addresses within a VPC, often used to separate public-facing services (API) from private ones (databases, model training nodes).

26. What is gRPC streaming, and why might it be preferred for ML inference pipelines?
Allows continuous streaming of requests/responses over a single connection (client-streaming, server-streaming, or bidirectional) — useful for streaming large inputs (e.g., audio) or token-by-token model outputs efficiently.

27. What is the role of a load balancer's health check in a model-serving cluster?
Periodically pings backend instances to verify they're responsive; unhealthy instances (e.g., a crashed model server) are automatically removed from the routing pool until they recover.

28. What is the difference between horizontal scaling of network traffic vs vertical scaling for network throughput?
Horizontal: adding more servers/instances behind a load balancer to handle more concurrent network requests. Vertical: upgrading a single server's network interface/bandwidth capacity — horizontal is generally preferred for elastic, fault-tolerant scaling.

29. What is an Ingress controller in Kubernetes, from a networking standpoint?
Manages external access (typically HTTP/HTTPS) to services running inside a Kubernetes cluster, handling routing rules, SSL termination, and load balancing to backend pods (e.g., model-serving pods).

30. Why does network latency matter more for real-time inference (e.g., chat assistants) than for batch inference?
Real-time inference requires low round-trip latency for responsive user experience (every network hop adds delay); batch inference processes large volumes offline where total throughput matters more than per-request latency.

7️⃣ AI (30 Qs)

1. What is the difference between AI, Machine Learning, and Deep Learning?
AI: broad field of making machines perform intelligent tasks. ML: subset of AI where systems learn patterns from data rather than explicit rules. Deep Learning: subset of ML using multi-layered neural networks, especially effective for unstructured data (images, text, audio).

2. What is the difference between supervised, unsupervised, and reinforcement learning?
Supervised: learns from labeled input-output pairs. Unsupervised: finds patterns/structure in unlabeled data (clustering, dimensionality reduction). Reinforcement: an agent learns via trial-and-error using rewards/penalties from interacting with an environment.

3. What is overfitting, and how is it detected/prevented?
Model memorizes training data noise instead of generalizable patterns, performing well on training but poorly on unseen data. Detected via train-vs-validation performance gap; prevented via regularization, dropout, more data, or early stopping.

4. What is the bias-variance tradeoff?
Bias: error from overly simplistic assumptions (underfitting). Variance: error from being overly sensitive to training data fluctuations (overfitting) — the goal is to find a model complexity that balances both for best generalization.

5. What is gradient descent, and what's the role of the learning rate?
An optimization algorithm that iteratively adjusts model parameters in the direction that reduces the loss function. Learning rate controls step size — too high can overshoot/diverge, too low makes training slow or stuck in local minima.

6. What is the difference between batch, mini-batch, and stochastic gradient descent?
Batch: uses the entire dataset per update (accurate but slow). Stochastic: uses one sample per update (fast but noisy). Mini-batch: uses small batches — a practical middle ground, most commonly used in deep learning training.

7. What is regularization, and name common types (L1/L2).
Techniques to reduce overfitting by penalizing model complexity. L1 (Lasso): adds absolute value of weights to loss, encourages sparsity (feature selection). L2 (Ridge): adds squared weights, discourages large weights without forcing them to zero.

8. What is dropout, and why is it used in neural networks?
Randomly "dropping" (zeroing out) a fraction of neurons during training — prevents co-adaptation of neurons, acting as a regularization technique that reduces overfitting.

9. What is the vanishing/exploding gradient problem?
In deep networks, gradients can shrink toward zero (vanishing) or grow uncontrollably (exploding) during backpropagation through many layers, hindering training — mitigated via techniques like ReLU activation, batch normalization, residual connections, and careful weight initialization.

10. What is backpropagation?
The algorithm used to compute gradients of the loss function with respect to each weight in a neural network, using the chain rule, propagating error backward from output to input layers to update weights via gradient descent.

11. What is the difference between a CNN and an RNN, and what data types are they suited for?
CNN (Convolutional Neural Network): uses convolutional filters to capture spatial patterns — suited for images. RNN (Recurrent Neural Network): processes sequences with memory of previous steps — suited for time-series/text, though largely superseded by Transformers for NLP.

12. What is transfer learning, and why is it valuable?
Reusing a model pretrained on a large dataset (e.g., ImageNet, large text corpora) and fine-tuning it on a smaller, task-specific dataset — saves compute/data requirements and often improves performance versus training from scratch.

13. What is the difference between fine-tuning and feature extraction in transfer learning?
Feature extraction: freeze pretrained layers, only train a new final layer on top. Fine-tuning: unfreeze some/all pretrained layers and continue training at a low learning rate, adapting deeper representations to the new task.

14. What are common evaluation metrics for classification, and when would you prefer precision over recall?
Accuracy, Precision, Recall, F1-score, ROC-AUC. Precision matters more when false positives are costly (e.g., spam filter blocking legitimate email); recall matters more when false negatives are costly (e.g., missing a fraud case or disease diagnosis).

15. What is a confusion matrix?
A table showing True Positives, True Negatives, False Positives, and False Negatives for a classification model — the basis for computing precision, recall, F1, and accuracy.

16. What is cross-validation, and why is it used?
Splitting data into multiple folds, training/validating across different combinations to get a more robust estimate of model performance — reduces the risk of overfitting to a single train-test split.

17. What is feature engineering, and why does it still matter in the deep learning era?
Creating/transforming input features to better represent the underlying problem for a model. Still matters for structured/tabular data problems and can significantly improve model performance even alongside deep learning approaches.

18. What is the difference between generative and discriminative models?
Discriminative: models the decision boundary/conditional probability P(y|x) directly (e.g., logistic regression, classifiers). Generative: models the joint probability P(x,y) and can generate new data samples (e.g., GANs, diffusion models, LLMs).

19. What is an embedding, and why is it fundamental to modern AI systems?
A dense vector representation of data (words, images, users) capturing semantic meaning/similarity in a continuous space — foundational for search, recommendation, and as input representations for neural networks including Transformers.

20. What is the difference between precision and recall in imbalanced datasets, and why is accuracy misleading there?
In imbalanced data (e.g., 95% negative class), a model predicting all-negative gets 95% accuracy but 0% recall on the positive class — precision/recall (and F1) give a truer picture of performance on the minority class.

21. What is model drift, and why does it matter in production AI systems?
Occurs when a model's performance degrades over time because the real-world data distribution shifts from what it was trained on (data drift) or the relationship between inputs and outputs changes (concept drift) — requires monitoring and periodic retraining.

22. What is the difference between online learning and batch (offline) learning?
Online: model updates incrementally as new data arrives, one sample/small batch at a time. Batch: model is retrained periodically on the full accumulated dataset — online learning adapts faster but can be less stable/harder to control.

23. What is a loss function, and how does it differ from an evaluation metric?
Loss function: differentiable objective optimized during training (e.g., cross-entropy, MSE) — must be mathematically suited for gradient-based optimization. Evaluation metric: measures real-world performance (e.g., accuracy, F1) — may not be directly differentiable, used for reporting/model selection rather than optimization.

24. What is hyperparameter tuning, and name common approaches.
Selecting the best configuration values (learning rate, batch size, number of layers) not learned during training. Approaches: Grid Search (exhaustive), Random Search (sampling), Bayesian Optimization (model-guided search), and more recently automated tools like Optuna.

25. What is the difference between a parametric and non-parametric model?
Parametric: fixed number of parameters regardless of data size (e.g., linear regression, neural networks) — faster but assumes a specific functional form. Non-parametric: complexity grows with data (e.g., k-NN, decision trees) — more flexible but can be slower/require more memory.

26. What is data leakage in ML, and give an example.
When information from outside the training dataset (often from the target/future) inadvertently influences model training, leading to overly optimistic performance that doesn't hold in production. Example: including a feature that's only known after the outcome occurs (like a "cancellation date" when predicting cancellations).

27. What is the exploration-exploitation tradeoff in reinforcement learning?
Balancing trying new actions to discover potentially better rewards (exploration) versus leveraging known good actions to maximize immediate reward (exploitation) — critical for effective RL agent training.

28. What is model interpretability, and why does it matter (e.g., SHAP, LIME)?
The degree to which a human can understand why a model made a specific prediction. Tools like SHAP/LIME approximate feature importance for individual predictions — important for trust, debugging, and regulatory compliance in sensitive domains (finance, healthcare).

29. What is the difference between AI model training and inference in terms of compute requirements?
Training: computationally intensive, requires forward + backward passes over large datasets repeatedly (often GPU/TPU clusters, hours-to-weeks). Inference: only forward pass on new inputs, much less compute per request, but must often be optimized for low latency at scale.

30. What is few-shot learning, and how does it relate to modern LLMs?
The ability of a model to perform a task correctly given only a few examples (or none, i.e., zero-shot) rather than extensive labeled training data — a hallmark capability of large pretrained language models due to broad pretraining, enabling prompting-based task adaptation without fine-tuning.

8️⃣ RAG (Retrieval-Augmented Generation) (30 Qs)

1. What is RAG, and what problem does it solve?
A technique combining a retrieval system with a generative LLM — the model retrieves relevant documents from an external knowledge base and uses them as context to generate answers, solving the problem of LLMs having static/outdated knowledge and reducing hallucination by grounding responses in real data.

2. What are the main components of a RAG pipeline?
Document ingestion/chunking → Embedding generation → Vector store indexing → Retriever (similarity search) → Context assembly → LLM generation using retrieved context + query.

3. Why is chunking necessary before embedding documents?
LLMs and embedding models have context/token limits, and overly large chunks dilute relevance in similarity search — chunking breaks documents into smaller, semantically coherent pieces for more precise retrieval.

4. What is the trade-off in choosing chunk size?
Small chunks: more precise retrieval but may lose surrounding context. Large chunks: retain more context but risk diluting relevance (retrieving a big chunk where only one sentence is actually relevant) and cost more tokens per retrieval.

5. What is chunk overlap, and why use it?
Including a portion of the previous chunk's text at the start of the next chunk — prevents important context from being awkwardly split across chunk boundaries, improving retrieval quality at sentence/idea boundaries.

6. What is an embedding model's role in RAG?
Converts text (queries and document chunks) into dense numerical vectors capturing semantic meaning, so similarity between query and documents can be computed mathematically (e.g., cosine similarity) rather than relying on exact keyword match.

7. What is the difference between dense retrieval and sparse retrieval (e.g., BM25)?
Sparse (BM25/TF-IDF): keyword-based, matches exact/similar terms, interpretable, works well for precise terminology. Dense: uses embeddings to capture semantic similarity even without exact word overlap — often combined (hybrid search) for best results.

8. What is hybrid search in RAG systems?
Combining sparse (keyword-based, e.g., BM25) and dense (embedding-based) retrieval scores, then merging/re-ranking results — captures both exact term matches and semantic similarity for more robust retrieval.

9. What is a re-ranker, and why add one after initial retrieval?
A second-stage model (often a cross-encoder) that re-scores the top-k retrieved documents more precisely against the query — initial retrieval (bi-encoder/ANN) is fast but less accurate; re-ranking improves final relevance at a small added latency cost.

10. What is the difference between a bi-encoder and a cross-encoder in retrieval?
Bi-encoder: encodes query and documents independently into vectors, compared via similarity (fast, scalable for large corpora). Cross-encoder: encodes query and document together, capturing richer interaction (more accurate but much slower — used only for re-ranking a small candidate set).

11. What is the "lost in the middle" problem in RAG context windows?
LLMs tend to pay less attention to information placed in the middle of a long context window compared to the beginning or end — relevant retrieved chunks placed in the middle of a large context may be under-utilized by the model.

12. How do you evaluate a RAG system's retrieval quality?
Metrics like Recall@k, Precision@k, and Mean Reciprocal Rank (MRR) measure whether relevant documents are retrieved and ranked highly; requires a labeled set of query-relevant-document pairs for evaluation.

13. How do you evaluate the generation quality of a RAG system end-to-end?
Using metrics/frameworks like RAGAS (faithfulness, answer relevance, context precision/recall), or human evaluation, and checking whether generated answers are grounded in retrieved context (faithfulness) rather than hallucinated.

14. What is "faithfulness" in RAG evaluation?
Whether the generated answer is actually supported by/derived from the retrieved context, rather than introducing information not present in the retrieved documents (a proxy for hallucination in RAG-specific settings).

15. What is the difference between RAG and simply fine-tuning an LLM on domain data?
RAG injects up-to-date/external knowledge at inference time without retraining, easily updatable by changing the document store. Fine-tuning bakes knowledge into model weights — better for adapting style/behavior but harder to update and can still hallucinate on facts not well-represented in training.

16. Why might you combine RAG with fine-tuning rather than choosing one?
Fine-tuning can teach the model domain-specific reasoning/style/format, while RAG supplies fresh, factual, retrievable knowledge — combining both often yields better accuracy and adaptability than either alone.

17. What is metadata filtering in RAG retrieval, and why is it useful?
Attaching metadata (date, source, category) to chunks and filtering retrieval by these fields before/alongside vector search — improves precision by narrowing the search space (e.g., only retrieve docs from a specific product line or time range).

18. What is query rewriting/expansion in RAG, and why is it used?
Reformulating or expanding the user's query (e.g., using an LLM) before retrieval to better match how relevant information is phrased in the document store — improves recall, especially for ambiguous or poorly-phrased queries.

19. What is multi-hop retrieval in RAG?
Retrieving information in multiple sequential steps, where the result of one retrieval informs the next query — needed for questions requiring reasoning across multiple documents (e.g., "What company did the CEO of X previously work at?").

20. What is the role of the vector database in a RAG system, and name common ANN indexing methods used.
Stores embeddings and enables fast similarity search at scale. Common ANN methods: HNSW (Hierarchical Navigable Small World graphs), IVF (Inverted File Index), PQ (Product Quantization) — trade off between search speed, accuracy, and memory.

21. What is context window truncation, and how does it affect RAG?
When retrieved context + query + generation exceeds the model's max token limit, content must be truncated/dropped — poor handling can cut off critical retrieved information, so retrieval ranking and context ordering matter.

22. What is a common cause of hallucination specifically in RAG systems despite having retrieved context?
The model ignoring or "overriding" retrieved context with its own parametric (pretrained) knowledge, especially when retrieved context is irrelevant, contradictory, or when the prompt doesn't clearly instruct the model to rely strictly on the provided context.

23. How would you reduce hallucination in a RAG pipeline through prompting?
Explicitly instruct the model to answer only using the provided context, to say "I don't know" if the answer isn't present, and optionally require citations/quotes pointing to the specific retrieved chunk used.

24. What is the difference between a naive RAG pipeline and an "agentic" RAG pipeline?
Naive RAG: single retrieve-then-generate pass. Agentic RAG: the LLM can iteratively decide to retrieve more, reformulate queries, use tools, or retrieve from multiple sources based on intermediate reasoning — more flexible for complex, multi-step questions.

25. What is the cold-start problem in RAG, and how might you mitigate it?
When the document/knowledge base is small, poorly indexed, or lacks coverage for certain query types, leading to poor retrieval. Mitigated by expanding/curating the corpus, adding synthetic Q&A pairs, or falling back to the LLM's parametric knowledge with a clear disclaimer.

26. How do you handle updates/deletions in a RAG knowledge base over time?
Re-embed and re-index updated documents, remove stale/deleted document vectors from the vector store, and version documents with timestamps/metadata so retrieval can prioritize the most current information.

27. What is the impact of embedding model choice on RAG quality?
Different embedding models vary in domain suitability (general vs. domain-specific), dimensionality, and multilingual support — a mismatched embedding model (e.g., general-purpose on highly technical/legal text) can significantly hurt retrieval relevance.

28. What is the difference between top-k retrieval and similarity threshold-based retrieval?
Top-k: always retrieves a fixed number of nearest documents regardless of actual relevance. Threshold-based: only retrieves documents above a similarity score cutoff — top-k risks including irrelevant filler, threshold-based risks retrieving nothing if the cutoff is too strict.

29. How would you design a RAG system to cite its sources?
Track chunk-to-document metadata through the pipeline, instruct the LLM (via prompt) to reference specific chunk IDs/sources when generating claims, and optionally post-process the output to map citations back to actual document links.

30. What are the main latency bottlenecks in a production RAG pipeline, and how would you address them?
Embedding the query, vector search, re-ranking (if used), and LLM generation are the main stages — addressed via caching frequent queries, using approximate (not exact) vector search, batching, smaller/faster re-rankers, and streaming generation output to reduce perceived latency.

9️⃣ TRANSFORMERS (30 Qs)

1. What is the core innovation of the Transformer architecture over RNNs?
Transformers process entire sequences in parallel using self-attention (rather than sequentially like RNNs), capturing long-range dependencies more effectively and enabling much faster training via parallelization on GPUs.

2. What is self-attention, in simple terms?
A mechanism where each token in a sequence computes a weighted relevance ("attention") to every other token, allowing the model to focus on the most contextually important words regardless of their distance in the sequence.

3. What are Query, Key, and Value vectors in attention?
Each token is projected into Query (what it's looking for), Key (what it offers to be matched against), and Value (the actual information it contributes) — attention score is computed from Query·Key similarity, then used to weight the Values.

4. What is the formula for scaled dot-product attention, and why is scaling needed?
Attention(Q,K,V) = softmax(QKᵀ/√dₖ)V — scaling by √dₖ (key dimension) prevents dot products from growing too large in magnitude, which would push softmax into regions with extremely small gradients.

5. What is multi-head attention, and why use multiple heads instead of one?
Running several attention operations in parallel with different learned projections, then concatenating results — allows the model to jointly attend to information from different representation subspaces (e.g., syntactic vs semantic relationships) simultaneously.

6. Why do Transformers need positional encoding?
Unlike RNNs, self-attention has no inherent notion of token order (it treats input as a set) — positional encodings (sinusoidal or learned) are added to embeddings to inject sequence order information.

7. What is the difference between an encoder-only, decoder-only, and encoder-decoder Transformer?
Encoder-only (e.g., BERT): bidirectional context, good for understanding/classification tasks. Decoder-only (e.g., GPT): autoregressive, generates text left-to-right, good for generation. Encoder-decoder (e.g., T5, original Transformer): encodes input then generates output, good for translation/summarization.

8. What is masked self-attention, and why is it used in decoders?
Prevents a token from attending to future tokens during training/generation by masking out (setting to -∞ before softmax) attention scores to subsequent positions — necessary to preserve autoregressive (left-to-right) generation validity.

9. What is the role of the feed-forward network (FFN) within a Transformer block?
A position-wise fully connected network (applied independently to each token) that adds non-linearity and additional representational capacity after the attention sub-layer — typically expands then projects back the dimensionality.

10. What is layer normalization, and why is it used in Transformers?
Normalizes activations across the feature dimension for each token independently — stabilizes and speeds up training by keeping activation distributions consistent across layers, unlike batch norm which normalizes across the batch dimension.

11. What is a residual (skip) connection, and why does it matter in deep Transformer stacks?
Adds the input of a sub-layer directly to its output (x + Sublayer(x)) — helps gradients flow through very deep networks without vanishing, enabling stable training of models with dozens of stacked layers.

12. What is the difference between BERT and GPT in terms of training objective?
BERT: trained with Masked Language Modeling (predict randomly masked tokens using bidirectional context) + Next Sentence Prediction. GPT: trained with causal/autoregressive language modeling (predict the next token given only preceding tokens).

13. What is tokenization, and why do modern LLMs use subword tokenization (e.g., BPE)?
Splitting text into units (tokens) the model processes. Subword tokenization (Byte-Pair Encoding, WordPiece) balances vocabulary size and handling of rare/unseen words by breaking them into common subword units rather than whole words or individual characters.

14. What is the time/memory complexity of self-attention with respect to sequence length, and why does it matter?
O(n²) in both time and memory with respect to sequence length n, because every token attends to every other token — this is why long-context models require specialized efficient attention mechanisms (sparse attention, linear attention, sliding window attention).

15. What are some methods to make attention more efficient for long sequences?
Sparse attention (attend to a subset of tokens), sliding window attention (local context only), linear attention approximations, and techniques like FlashAttention (IO-aware exact attention computation that reduces memory reads/writes without approximation).

16. What is FlashAttention, and why is it significant?
An optimized implementation of exact attention that reduces memory bandwidth bottlenecks by fusing operations and avoiding materializing the full attention matrix in slow GPU memory — speeds up training/inference without changing the underlying math.

17. What is KV caching, and why is it important for autoregressive generation?
Storing previously computed Key and Value vectors during generation so they don't need to be recomputed for each new token — critical for efficient inference, since without it, generating each new token would require reprocessing the entire sequence from scratch.

18. What is the difference between pretraining and fine-tuning for Transformer-based LLMs?
Pretraining: training on massive unlabeled text corpora with a general objective (next-token prediction) to learn broad language understanding. Fine-tuning: further training on smaller, task-specific (often labeled) data to specialize the model's behavior for a target use case.

19. What is RLHF (Reinforcement Learning from Human Feedback), and why is it used after pretraining?
A technique where a model is further trained using human preference data (via a reward model and RL, e.g., PPO) to align its outputs with human preferences for helpfulness, harmlessness, and honesty — pretraining alone doesn't guarantee outputs match desired behavior/style.

20. What is the difference between absolute and relative positional encodings?
Absolute: fixed encoding based on a token's exact position in the sequence (e.g., original sinusoidal encoding). Relative: encodes the distance/relationship between token pairs rather than fixed positions — often generalizes better to sequence lengths not seen during training (e.g., RoPE - Rotary Position Embedding).

21. What is RoPE (Rotary Positional Embedding), and why do many modern LLMs use it?
Encodes positional information by rotating query/key vectors in a way that naturally captures relative position through the dot product — used in models like LLaMA because it extrapolates better to longer sequences than fixed absolute encodings.

22. What is the difference between temperature and top-k/top-p sampling during generation?
Temperature: scales the logits before softmax to control randomness (higher = more random, lower = more deterministic). Top-k: restricts sampling to the k most likely next tokens. Top-p (nucleus sampling): restricts sampling to the smallest set of tokens whose cumulative probability exceeds p — all control the diversity/creativity vs. determinism trade-off in generation.

23. What is the difference between greedy decoding and beam search?
Greedy: always picks the single highest-probability next token at each step (fast but can miss globally better sequences). Beam search: keeps track of the top-k candidate sequences at each step, exploring more possibilities before selecting the best overall — generally higher quality but more computationally expensive.

24. What causes repetition in Transformer-generated text, and how can it be mitigated?
Autoregressive models can get stuck favoring previously generated tokens/phrases due to how probability mass accumulates. Mitigated via repetition penalties, no-repeat n-gram constraints, temperature/top-p sampling, or contrastive search decoding methods.

25. What is the difference between a Transformer encoder's bidirectional attention and a decoder's causal attention?
Encoder: each token attends to all tokens (both before and after) in the sequence — good for understanding full context. Decoder (causal): each token can only attend to itself and previous tokens (masked) — necessary to preserve valid left-to-right generation.

26. What is model distillation in the context of Transformers, and why is it used?
Training a smaller "student" model to mimic the outputs/behavior of a larger "teacher" model — produces a smaller, faster model retaining much of the teacher's performance, useful for reducing inference cost/latency in production.

27. What is quantization, and how does it apply to deploying large Transformer models?
Reducing the numerical precision of model weights/activations (e.g., from 32-bit floats to 8-bit or 4-bit integers) to reduce memory footprint and speed up inference, with some trade-off in accuracy — essential for running large LLMs on limited hardware.

28. What is the difference between LoRA (Low-Rank Adaptation) and full fine-tuning?
Full fine-tuning updates all model weights (expensive, large storage per task). LoRA freezes the original weights and injects small trainable low-rank matrices into specific layers — drastically reduces the number of trainable parameters and storage needed while achieving comparable task performance.

29. What is the context length limit of a Transformer, and why can't it simply be made infinite?
The maximum number of tokens the model can process in one pass, constrained by the quadratic (O(n²)) compute/memory cost of self-attention and the fact that positional encodings are typically trained/effective only up to a certain length — extending it requires architectural changes or efficient attention variants.

30. Why are Transformers considered better suited than RNNs for transfer learning at scale?
Their parallelizable architecture allows efficient training on massive datasets/hardware, and self-attention captures rich contextual representations that generalize well — this combination enabled the pretrain-then-fine-tune/prompt paradigm that underlies modern foundation models (BERT, GPT, T5, etc.).

🔟 SYSTEM DESIGN (30 Qs)

1. What are the first questions you should ask when starting a system design interview?
Clarify functional requirements (what must the system do), non-functional requirements (scale, latency, availability needs), expected traffic/data volume, and constraints (budget, existing infrastructure) before jumping into design.

2. What is the difference between functional and non-functional requirements?
Functional: specific behaviors the system must perform (e.g., "users can upload images for classification"). Non-functional: quality attributes like scalability, latency, availability, security — both must be defined to design an appropriate architecture.

3. How would you design a scalable ML model-serving API?
Load balancer → multiple stateless model server replicas (containerized) → autoscaling based on traffic → caching for repeated inputs → async queue for heavy/batch requests → monitoring/logging for latency and errors.

4. What is back-of-the-envelope estimation, and why is it important in system design?
Quick rough calculations (requests/sec, storage needs, bandwidth) to gauge system scale before designing — ensures the proposed architecture is appropriately sized rather than over- or under-engineered.

5. How would you design a system to serve millions of real-time recommendation requests per day?
Precompute/cache candidate recommendations offline (batch), use a fast online ranking model for final personalization at request time, employ a feature store for low-latency feature lookups, and scale horizontally behind a load balancer with caching for popular queries.

6. What is the difference between a monolith and a distributed system from a design trade-off perspective?
Monolith: simpler to build/debug/deploy initially, but scaling and team ownership become harder as complexity grows. Distributed: better scalability and fault isolation, but introduces complexity in consistency, networking, and debugging across services.

7. How would you design a rate limiter for an ML inference API?
Use algorithms like Token Bucket or Sliding Window Counter, store request counts per client in a fast store (Redis), and reject/queue requests exceeding the configured limit — balances fairness and protecting backend model servers from overload.

8. What is a common design pattern for handling long-running ML inference requests (e.g., large batch jobs) without blocking the client?
Accept the request, return an immediate job ID/acknowledgment, process asynchronously via a queue/worker pool, and let the client poll a status endpoint or receive a webhook/callback when the result is ready.

9. How would you design a system to A/B test two different ML models in production?
Route a percentage of traffic to each model variant (via load balancer or feature flag), log predictions and downstream outcomes tagged by variant, and compare business/model metrics statistically before deciding which to fully roll out.

10. What is the role of a feature store in a system design for real-time ML predictions?
Provides consistent, low-latency access to precomputed features for both training (batch/historical) and serving (real-time), preventing train-serve skew and reducing redundant feature computation logic across services.

11. How would you design a system for real-time fraud detection with sub-100ms latency requirements?
Stream incoming transactions through a fast feature-lookup layer (in-memory feature store), use a lightweight, optimized model (possibly quantized) for scoring, and route only flagged/high-risk cases to slower, more thorough downstream review — prioritizing speed on the critical path.

12. What is the CAP theorem's practical implication when designing a distributed ML feature store?
You must choose to prioritize either strong Consistency or high Availability during a network partition — for real-time ML serving, Availability is often prioritized (serving slightly stale features) over strict consistency, since a slow/unavailable system is usually worse than marginally outdated data.

13. How would you design a system to handle sudden traffic spikes to a model API (e.g., a viral product launch)?
Autoscaling policies based on request queue length/CPU, a request queue/buffer to smooth bursts, graceful degradation (e.g., serving a cached/simpler fallback response under extreme load), and pre-warmed instances if spikes are predictable.

14. What is graceful degradation, and give an ML-specific example.
Designing a system to maintain reduced but functional service under failure/overload rather than failing completely — e.g., falling back to a simpler/cached recommendation list if the personalized ranking model service is overloaded or down.

15. How would you design a logging/monitoring system for a production ML pipeline?
Log requests/predictions/latencies centrally (e.g., ELK stack or cloud logging), track model-specific metrics (prediction distribution, confidence scores) via dashboards, set up alerts for anomalies (latency spikes, error rate increases, drift indicators).

16. What is the difference between designing for high availability vs high consistency in an ML system, and which usually matters more?
High availability ensures the system keeps responding even if some data is slightly stale/some nodes fail; high consistency ensures all reads reflect the latest write. For most ML serving use cases (recommendations, predictions), availability is prioritized since users prefer a slightly-stale-but-fast answer over no answer.

17. How would you design a data pipeline to handle both batch training and real-time inference consistently?
Build a shared feature transformation layer (e.g., using a feature store or shared feature engineering code/library) so the exact same logic computes features for both offline training data and online serving requests, avoiding train-serve skew.

18. What are the key considerations when designing for multi-region deployment of an ML service?
Data residency/compliance requirements, latency (serving users from the nearest region), data replication/consistency across regions, and failover strategy if one region goes down.

19. How would you design a system to detect and handle model staleness/drift in production?
Continuously log incoming feature distributions and prediction outputs, compare against training data baselines using statistical tests (e.g., KS test, PSI), trigger alerts/automated retraining pipelines when drift exceeds a threshold.

20. What trade-offs would you consider between synchronous and asynchronous design for an ML pipeline step (e.g., feature computation)?
Synchronous: simpler, immediate consistency, but can create latency bottlenecks/tight coupling. Asynchronous: better scalability and fault isolation via queues, but adds complexity (eventual consistency, needing to track job/task state).

21. How would you design a system to support both real-time and batch prediction using the same trained model?
Package the model behind a shared prediction service/library, expose a real-time API endpoint for low-latency single requests, and use the same model artifact in a scheduled batch job (e.g., Spark job) for bulk scoring — avoiding duplicate model logic.

22. What is idempotency's role in system design, and where would you apply it in an ML pipeline?
Ensures repeated execution of an operation (e.g., retrying a failed feature-computation job) produces the same result without unintended side effects (like duplicate database writes) — critical wherever retries are expected in distributed pipelines.

23. How would you design a caching layer for an ML prediction API, and what would you cache?
Cache predictions for identical/frequent input requests (e.g., using Redis with input hash as key), set appropriate TTLs based on how often the model/data changes, and consider cache invalidation triggers on model redeployment.

24. What is a common design pitfall when scaling a model-serving system horizontally with a stateful model (e.g., holding conversation history)?
Sticky sessions become necessary (routing a user's requests consistently to the same instance holding their state) or state must be externalized (e.g., stored in Redis/a database) so any instance can serve any request — otherwise horizontal scaling breaks statefulness.

25. How would you design a system for human-in-the-loop review of low-confidence model predictions?
Route predictions below a confidence threshold to a review queue, present them via a UI to human reviewers, feed reviewed labels back into a retraining/feedback loop, while high-confidence predictions proceed automatically — balances automation with accuracy on uncertain cases.

26. What are the key design considerations for a multi-tenant ML platform serving multiple internal teams/models?
Resource isolation (avoiding one team's heavy usage starving others), per-tenant rate limiting/quotas, separate logging/monitoring per tenant, and a consistent deployment/versioning interface across teams' models.

27. How would you design for cost efficiency when serving a large LLM at scale?
Use dynamic batching to maximize GPU utilization, quantize the model to reduce compute/memory needs, autoscale down during low traffic, cache common queries/responses, and consider tiered serving (smaller/cheaper model for simple queries, larger model only when needed).

28. What is the role of a message queue in decoupling a multi-stage ML inference pipeline (e.g., preprocessing → model → postprocessing)?
Each stage publishes results to a queue/topic that the next stage consumes, allowing each component to scale independently, handle failures/retries in isolation, and smooth out load spikes without one stage blocking another.

29. How would you design disaster recovery for a critical ML inference service?
Maintain multi-region/multi-AZ redundancy, regular backups of model artifacts and configuration, automated failover with health checks, and a documented runbook/tested recovery procedure with defined RTO/RPO targets.

30. What is the difference between designing for scalability and designing for reliability, and how do they sometimes conflict?
Scalability focuses on handling increasing load efficiently; reliability focuses on consistent correct behavior/uptime even during failures. They can conflict when scaling introduces more failure points (more services/nodes) — good design uses redundancy, circuit breakers, and monitoring to achieve both simultaneously.

1️⃣1️⃣ SCALING (30 Qs)

1. What is the difference between horizontal and vertical scaling?
Vertical: adding more resources (CPU, RAM, GPU) to a single existing machine — simple but limited by hardware ceilings. Horizontal: adding more machines/instances to distribute load — more scalable and fault-tolerant, the standard approach for large ML serving systems.

2. What is autoscaling, and what metrics commonly trigger it?
Automatically adjusting the number of running instances based on real-time demand. Common trigger metrics: CPU/GPU utilization, request queue length, memory usage, or custom metrics like requests-per-second or inference latency.

3. What is the difference between scaling out reads vs scaling out writes in a database?
Reads: relatively easy to scale via replicas (multiple read-only copies serving queries). Writes: harder to scale since all replicas must stay consistent — often requires sharding or a single write-master with careful synchronization.

4. What is model serving batching, and how does it help scaling?
Grouping multiple incoming inference requests together into a single forward pass through the model — significantly improves GPU utilization/throughput since GPUs are optimized for parallel batch computation, at a small cost of added per-request latency.

5. What is the difference between static batching and dynamic batching?
Static: waits for a fixed batch size or fixed timeout before processing, less flexible. Dynamic: continuously groups whatever requests have arrived within a short time window into variable-sized batches — better balances latency and throughput under variable traffic.

6. What is horizontal pod autoscaling in Kubernetes, and how does it apply to ML model serving?
Automatically increases/decreases the number of running pod replicas of a model-serving deployment based on observed metrics (CPU, custom inference queue depth) — ensures the service scales with demand without manual intervention.

7. What is the bottleneck typically limiting scaling of GPU-based model inference, and how is it addressed?
GPU memory and compute throughput are common bottlenecks — addressed via model quantization, batching, using multiple GPU instances behind a load balancer, or model parallelism for very large models that don't fit on a single GPU.

8. What is data parallelism vs model parallelism in scaling ML training?
Data parallelism: same model replicated across multiple devices, each processing a different data batch, gradients aggregated/synced. Model parallelism: the model itself is split across multiple devices (e.g., different layers on different GPUs) when it's too large to fit on one device.

9. What is the difference between scaling for training workloads vs scaling for inference workloads?
Training: typically batch-oriented, throughput-focused, can tolerate longer per-job time, benefits from large multi-GPU/multi-node clusters. Inference: often latency-sensitive, request-driven, needs to scale elastically with unpredictable real-time traffic patterns.

10. What is a stateless service's advantage for horizontal scaling?
Since it holds no session-specific data between requests, any instance can handle any request — enabling simple load balancing and seamless addition/removal of instances without needing to worry about routing users to a specific server.

11. What is database read replica scaling, and its limitation?
Adding additional read-only copies of a database to distribute read query load across multiple servers — limitation: replicas may lag behind the primary (replication lag), risking slightly stale reads (eventual consistency).

12. What is connection pooling's role in scaling database-backed services?
Reuses a limited set of database connections across many requests instead of opening a new connection per request — prevents connection exhaustion and reduces overhead as request volume scales up.

13. What is the difference between scaling a stateless API layer and scaling a stateful cache/database layer?
Stateless API: trivially horizontally scalable (just add more instances behind a load balancer). Stateful layers (databases/caches) require careful strategies (replication, sharding, partitioning) since data consistency and distribution must be actively managed.

14. What is the "thundering herd" problem, and how does it relate to scaling?
Occurs when a large number of clients/processes simultaneously request the same resource at once (e.g., cache expiry causing all requests to hit the database simultaneously) — overwhelms the backend; mitigated via staggered expiry, request coalescing, or locking mechanisms.

15. What is elastic scaling, and why is it particularly valuable for ML workloads with variable traffic (e.g., seasonal e-commerce recommendations)?
Automatically scaling resources up during high-demand periods and down during low-demand periods — minimizes cost by not over-provisioning for peak capacity permanently, while still handling traffic spikes.

16. What is the difference between scaling up a single large model vs scaling out with model ensembles or multiple smaller specialized models?
Scaling up: one large model requiring significant per-request compute (higher accuracy potentially, but costly/slower). Scaling out with specialized smaller models: route requests to the appropriate lightweight model based on query type — can reduce average latency/cost while maintaining acceptable accuracy.

17. What is the role of a CDN in scaling globally distributed ML-powered applications?
Caches static assets (and sometimes cacheable API responses) at edge locations close to users worldwide — reduces load on origin servers and improves latency for geographically distributed user bases.

18. What is vertical partitioning vs horizontal partitioning (sharding) as a scaling strategy?
Vertical: splitting a database by columns/features across different servers (e.g., user profile data vs. transaction data on separate DBs). Horizontal (sharding): splitting by rows across servers (e.g., users A-M on one shard, N-Z on another) — both distribute load, chosen based on access patterns.

19. What is a common scaling challenge specific to serving very large language models (tens/hundreds of billions of parameters)?
The model may not fit in a single GPU's memory, requiring model/tensor parallelism across multiple GPUs, which adds inter-GPU communication overhead — balancing parallelism strategy against latency and hardware cost becomes a major design challenge.

20. What is the difference between scaling reads via caching vs scaling reads via read replicas?
Caching: stores frequently accessed results in fast in-memory storage (e.g., Redis), reducing load on the database entirely for repeat queries. Read replicas: still queries a database (just a different instance), useful for queries too varied/unique to benefit much from caching.

21. What is queue-based load leveling, and how does it help scale under bursty traffic?
Incoming requests are placed into a queue and processed by workers at a sustainable rate, rather than directly overwhelming backend services during traffic spikes — smooths bursty load into a steady processing rate, trading some latency for stability.

22. What is the difference between scaling a monolithic ML pipeline vs a microservices-based ML pipeline?
Monolithic: must scale the entire pipeline together even if only one stage (e.g., preprocessing) is the actual bottleneck — inefficient. Microservices: each stage (ingestion, feature computation, inference) can be scaled independently based on its specific load, which is more resource-efficient.

23. What is a common pitfall when auto-scaling stateful ML training jobs (e.g., distributed training)?
Adding/removing nodes mid-training can disrupt gradient synchronization or require complex checkpointing/resharding logic — unlike stateless inference scaling, training scaling often requires careful coordination (e.g., via frameworks like Horovod or PyTorch Distributed) rather than simple elastic autoscaling.

24. What is the role of load testing in preparing an ML system to scale?
Simulating high traffic/load before production deployment to identify bottlenecks, determine appropriate autoscaling thresholds, and validate that the system meets latency/throughput SLAs under expected (and peak) load conditions.

25. What is vertical scaling's key limitation for GPU-based ML workloads specifically?
There's a hard ceiling on how much GPU compute/memory a single machine can have (limited by available hardware configurations), so beyond a certain point, horizontal scaling (multiple machines/GPUs) becomes necessary regardless of budget.

26. What is the difference between scaling for throughput and scaling for latency in a model-serving context?
Throughput scaling: maximizing total requests processed per second (often via batching, more replicas). Latency scaling: minimizing time-per-request (often means smaller batches, faster hardware, or model optimization) — these two goals frequently trade off against each other.

27. What is sharding a vector database, and why might it become necessary at scale?
Splitting a large collection of embeddings across multiple nodes/partitions (e.g., by ID range or via clustering) when a single node can't hold or efficiently search the full index in memory — necessary once embedding counts reach hundreds of millions+.

28. What is a common strategy to scale an ML feature-serving layer to support both low-latency online lookups and large-scale offline training reads?
Maintain two synchronized stores: a fast key-value store (e.g., Redis/DynamoDB) for low-latency online serving, and a scalable batch/offline store (e.g., a data warehouse or Parquet files on object storage) for training — both fed from the same underlying feature computation pipeline.

29. What is graceful scale-down, and why does it matter for ML inference clusters?
Ensuring in-flight requests complete before an instance is terminated during scale-down (rather than abruptly killing it), typically via connection draining/health check deregistration — prevents dropped requests when autoscalers reduce capacity.

30. Why is horizontal scaling generally preferred over vertical scaling for production ML services, despite added complexity?
Horizontal scaling avoids hardware ceilings, improves fault tolerance (no single point of failure), and allows more granular, cost-efficient capacity adjustments matching real-time demand — the added complexity (load balancing, statelessness, distributed coordination) is a worthwhile trade-off at meaningful scale.

1️⃣2️⃣ LOAD BALANCING (30 Qs)

1. What is a load balancer, and why is it essential for ML model serving?
A component that distributes incoming requests across multiple backend instances (model servers) to prevent any single instance from being overwhelmed — improves availability, throughput, and fault tolerance for production inference systems.

2. What is the difference between Layer 4 (L4) and Layer 7 (L7) load balancing?
L4: routes traffic based on IP/port information only (fast, protocol-agnostic). L7: inspects actual request content (URL path, headers, payload) — enables smarter routing, e.g., sending /predict-v1 and /predict-v2 requests to different model versions.

3. What is round robin load balancing, and what's its main limitation?
Distributes requests sequentially and equally across all available servers. Limitation: doesn't account for server load/capacity differences — a slower or overloaded server still gets an equal share, potentially becoming a bottleneck.

4. What is weighted round robin, and when would you use it?
Assigns different weights to servers based on their capacity (e.g., a bigger GPU instance gets more requests than a smaller one) — used when backend instances have heterogeneous compute power.

5. What is least connections load balancing?
Routes each new request to the server currently handling the fewest active connections — better suited than round robin when requests have variable processing times (common in ML inference where input size varies).

6. What is least response time load balancing?
Routes requests to the server with the lowest current response time (combining active connections and latency) — aims to actively minimize perceived latency for the end user.

7. What is IP hash-based load balancing, and why might it be used?
Routes requests based on a hash of the client's IP address, ensuring the same client consistently reaches the same server — useful for maintaining session affinity without external state storage.

8. What is sticky session (session affinity), and when is it needed for ML services?
Ensures a client's requests are always routed to the same backend instance — needed for stateful services (e.g., a conversational AI holding chat context in-memory), though generally avoided in favor of externalized state where possible for better scalability.

9. What is a health check in load balancing, and why is it critical?
Periodic probes (e.g., HTTP ping to a /health endpoint) sent to backend instances to verify they're responsive — unhealthy instances (e.g., a crashed model server or one stuck in an OOM state) are automatically removed from the routing pool.

10. What is the difference between active and passive health checks?
Active: load balancer proactively pings instances at intervals. Passive: load balancer infers health from actual request outcomes (e.g., timeouts/errors on real traffic) — active checks catch issues faster without waiting for real user impact.

11. What is a global load balancer, and how does it differ from a regional one?
Global: distributes traffic across multiple geographic regions/data centers (often via DNS-based routing), directing users to the nearest/healthiest region. Regional: distributes traffic among servers within a single data center/region.

12. What is DNS-based load balancing, and what's a drawback?
Uses DNS to resolve a domain to different IPs (rotating or based on geography) — drawback: DNS caching by clients/resolvers can cause stale routing decisions to persist longer than intended, reducing responsiveness to backend failures.

13. What is the difference between a hardware load balancer and a software load balancer?
Hardware: dedicated physical appliances (e.g., F5), high performance but costly and less flexible. Software: load balancing implemented via software (Nginx, HAProxy, cloud-native load balancers) — more flexible, cost-effective, and common in modern cloud/container-based ML deployments.

14. Why might load balancing be more challenging for GPU-based inference services compared to typical stateless web services?
GPU instances often have significant per-request processing time variance (based on input size/batch), limited concurrent capacity per GPU, and benefit from request batching — naive round-robin can lead to poor GPU utilization compared to load-aware or queue-based routing.

15. What is client-side load balancing, and how does it differ from a centralized load balancer?
The client itself (or a library/sidecar) decides which backend instance to call, often using a shared registry of healthy instances — avoids a single centralized load balancer bottleneck but pushes routing logic complexity to each client.

16. What is the role of a load balancer in a Kubernetes-based ML deployment?
A Kubernetes Service (with a load balancer type or Ingress controller) distributes traffic across pod replicas of a model-serving deployment, working alongside the Horizontal Pod Autoscaler to route to healthy, available pods.

17. What is connection draining in load balancing?
When an instance is being removed from rotation (e.g., during scale-down or deployment), the load balancer stops sending new requests to it but allows in-flight requests to complete gracefully before terminating it.

18. What is the difference between load balancing and API gateway routing?
Load balancing purely distributes traffic across replicas of the same service for availability/throughput. API gateway routing directs different types of requests to entirely different services/endpoints (e.g., routing /auth vs /predict to different backend services) — often layered together in practice.

19. What is a common failure mode if load balancing doesn't account for GPU memory/queue depth in ML serving?
Requests can get routed to an already-saturated GPU instance causing out-of-memory errors or severe latency spikes, while other instances sit underutilized — solved via custom load-aware routing based on queue length or GPU utilization metrics rather than simple connection count.

20. What is the difference between horizontal scaling and load balancing, and how do they relate?
Horizontal scaling is adding more instances to handle load; load balancing is the mechanism that actually distributes incoming traffic across those instances — scaling without proper load balancing wouldn't effectively utilize the added capacity.

21. What is a load balancer's role during a canary deployment of a new ML model?
Routes a small, controlled percentage of traffic to the new model version while the majority continues to the stable version, enabling safe performance comparison before a full rollout.

22. What is the "hot spot" problem in load balancing, and how can it occur in ML systems?
Occurs when load isn't evenly distributed, causing some servers to be overloaded ("hot") while others remain idle — in ML systems, this can happen if certain requests (e.g., very large inputs) consistently route to and overload the same instance.

23. What is consistent hashing, and why is it useful for load-balanced caching layers?
A hashing technique that minimizes redistribution of keys when nodes are added/removed (unlike simple modulo hashing) — useful for distributed caches supporting ML feature lookups, reducing cache misses during scaling events.

24. What is the difference between proactive (predictive) and reactive load balancing/scaling?
Reactive: responds to current load metrics after they change (may lag behind sudden spikes). Proactive: uses historical patterns or forecasts (e.g., known traffic surges) to pre-scale/redistribute load ahead of demand.

25. Why might request batching complicate traditional load balancing strategies for ML inference?
Since batching groups multiple requests together at the server before processing, simple per-request load balancing metrics (like active connections) may not accurately reflect true server load — load balancers may need custom logic aware of batch queue depth instead.

26. What is a reverse proxy's relationship to load balancing?
A reverse proxy (like Nginx) often performs load balancing as one of its functions, sitting in front of backend servers and distributing incoming requests — load balancing is a common feature/use case of reverse proxies, not a separate distinct tool.

27. What is the impact of an improperly configured load balancer timeout on ML inference services?
If the load balancer's timeout is shorter than typical model inference time (especially for large models/batches), it may prematurely terminate/retry legitimate slow requests, causing wasted compute and potential request duplication.

28. What is multi-region active-active load balancing, and its benefit for global ML services?
Traffic is actively served from multiple regions simultaneously (not just failover) — improves latency for geographically distributed users and provides redundancy, though requires careful data consistency/synchronization design.

29. What is the difference between load balancing at the infrastructure level vs application-level request routing logic (e.g., model selection)?
Infrastructure load balancing distributes traffic across identical replicas for availability/throughput; application-level routing makes business logic decisions (e.g., which specific model version or specialized model to invoke based on request content) — both can coexist in a layered architecture.

30. How would you design load balancing for a system serving multiple different-sized ML models (e.g., a small and a large model) behind one API?
Route requests to model-specific backend pools based on which model is needed (via L7 routing), load balance within each pool independently since resource needs/capacity differ significantly between the small and large model instances.

1️⃣3️⃣ HALLUCINATIONS (30 Qs)

1. What is hallucination in the context of LLMs?
When a model generates text that is factually incorrect, fabricated, or unsupported by its training data or provided context, but presented confidently as if true.

2. What are the two broad categories of hallucination often distinguished in research?
Intrinsic hallucination: output contradicts the given source/context directly. Extrinsic hallucination: output introduces information that can't be verified from the source/context at all (neither confirmed nor contradicted).

3. Why do LLMs hallucinate at a fundamental level?
LLMs are trained to predict the statistically most plausible next token based on patterns learned from training data — they optimize for fluency/plausibility, not verified truth, so they can generate confident-sounding text that isn't factually grounded.

4. What is the difference between hallucination and simply being "wrong" due to outdated knowledge?
Outdated knowledge: the model gives an answer that was true at training time but has since changed (a knowledge-cutoff issue). Hallucination: the model fabricates information that was never true or invents details/sources that don't exist at all.

5. How does RAG help reduce (but not eliminate) hallucination?
By grounding generation in retrieved, verifiable documents rather than relying purely on the model's parametric memory — reduces fabrication of facts, though the model can still ignore/misinterpret the retrieved context or hallucinate details not present in it.

6. What is a common cause of hallucination even when correct context is retrieved in a RAG system?
The model may default to its own pretrained (parametric) knowledge instead of strictly using the provided context, especially if the prompt doesn't explicitly instruct it to rely only on the retrieved information.

7. What is "faithfulness" as a hallucination-related metric?
Measures whether a generated statement is actually supported by/traceable to the provided source context — a core evaluation metric specifically for RAG and summarization systems to detect hallucination relative to given input.

8. How can prompting reduce hallucination?
Explicitly instructing the model to only answer based on given context, to state "I don't know" when uncertain, to cite sources, and using few-shot examples demonstrating appropriately cautious/grounded responses.

9. What is the role of temperature in hallucination risk during generation?
Higher temperature increases randomness/creativity in token selection, which can increase the likelihood of the model generating less probable (and potentially less factual) continuations — lower temperature generally produces more conservative, deterministic (though not necessarily always more accurate) outputs.

10. What is self-consistency checking, and how does it help detect hallucination?
Generating multiple responses to the same prompt (often with some randomness) and checking for agreement across them — if answers diverge significantly, it can signal the model is uncertain or hallucinating rather than recalling a stable fact.

11. What is a "confabulation," and how does it relate to LLM hallucination?
A term (borrowed from psychology) sometimes used to describe an LLM confidently generating plausible-sounding but fabricated content, without any intent to deceive — emphasizing that hallucination arises from the generative process itself, not malicious intent.

12. How does fine-tuning on domain-specific data affect hallucination risk?
Can reduce hallucination on in-domain queries by better aligning the model's parametric knowledge with the target domain, but may not fully eliminate hallucination on edge cases, and can sometimes introduce overconfidence if the fine-tuning data was itself imperfect.

13. What is the difference between hallucination in open-domain generation vs. task-specific generation (e.g., summarization)?
Open-domain: model can fabricate entirely novel "facts" about the world. Summarization: hallucination specifically means introducing details/claims not present in the source document being summarized — a narrower, more directly verifiable form of hallucination.

14. What is groundedness, and how is it evaluated?
The degree to which a model's output is supported by verifiable evidence/context. Evaluated via automated methods (NLI-based entailment checking between output and source, RAGAS-style metrics) or human annotation comparing claims against source documents.

15. What is the role of citation/attribution in mitigating perceived hallucination risk?
Requiring the model to cite specific source passages for claims allows users (or automated checks) to verify statements against the original document — doesn't prevent hallucination outright but makes it detectable and builds appropriate user trust/skepticism.

16. What is hallucination "snowballing," and why is it dangerous in multi-turn conversations?
Once a model states an incorrect fact, subsequent responses may build on and reinforce that false premise (since it's now part of the conversation context) — leading to increasingly elaborate and confident fabrications compounding over the conversation.

17. How does chain-of-thought (CoT) prompting affect hallucination, both positively and negatively?
Positively: forcing step-by-step reasoning can help the model catch inconsistencies before reaching a final answer. Negatively: the reasoning steps themselves can contain fabricated "facts" that then get treated as established premises for the final answer, compounding error.

18. What is the difference between hallucination and bias in LLM outputs?
Hallucination: generating factually false/fabricated information. Bias: systematically skewed outputs reflecting imbalances or stereotypes present in training data — related but distinct problems, though both stem from training data limitations and require different mitigation strategies.

19. What is a hallucination benchmark, and name an example type of evaluation it might use.
A standardized dataset/method to measure a model's tendency to hallucinate, often using known factual Q&A pairs and checking answer correctness, or using NLI models to check whether generated claims are entailed by a reference source.

20. Why can't hallucination be completely eliminated with current LLM architectures?
Because LLMs generate text via probabilistic next-token prediction without an internal, verified "ground truth" checking mechanism — even highly capable models lack a built-in way to be certain their generated claims are true rather than merely statistically plausible.

21. What is retrieval-augmented generation's limitation in fully preventing hallucination when the knowledge base itself is incomplete?
If relevant information simply isn't in the retrieved documents, the model may either honestly say it doesn't know (ideal) or fall back to fabricating an answer from its parametric knowledge (hallucination) — RAG only helps when the needed information actually exists and is successfully retrieved.

22. What is calibration in the context of LLM confidence and hallucination?
Whether a model's expressed confidence (or the probability it assigns) actually correlates with the likelihood its answer is correct — poorly calibrated models may state hallucinated facts with the same confidence as verified ones, making hallucination harder for users to detect.

23. How can structured output formats (e.g., requiring JSON with specific fields) help reduce perceived hallucination impact?
By constraining the model's output space and making it easier to programmatically validate/cross-check specific fields against known data sources, catching inconsistencies before they reach the end user.

24. What is the role of human-in-the-loop review in managing hallucination risk in production systems?
Routing high-stakes or low-confidence outputs to human reviewers before they're acted upon or shown to end users — an operational safeguard rather than a model-level fix, important in domains like healthcare/legal/finance.

25. What is "sycophantic" hallucination, and why does it occur?
When a model generates an answer that agrees with or flatters the user's stated belief/framing rather than providing an accurate/independent answer — often an artifact of RLHF training that over-optimized for being agreeable/well-received by human raters.

26. How does ambiguous or underspecified prompting increase hallucination risk?
When a query lacks necessary context/specificity, the model may "fill in the gaps" with plausible-sounding assumptions rather than asking for clarification, increasing the chance of fabricated details being introduced into the response.

27. What is the difference between factual hallucination and reasoning/logical hallucination?
Factual: fabricating incorrect facts/entities/dates. Reasoning hallucination: following a flawed logical chain that appears coherent step-by-step but reaches an incorrect conclusion — both undermine reliability but require different detection approaches (fact-checking vs logical verification).

28. What is an NLI (Natural Language Inference) model's role in hallucination detection?
Used to check whether a generated claim is "entailed by," "contradicts," or is "neutral" with respect to a source document — a common automated technique for scoring faithfulness in RAG/summarization pipelines without needing human review of every output.

29. Why might increasing model size not fully solve hallucination, even though it generally improves overall capability?
Larger models can be more fluent and confident, which can actually make hallucinations more convincing/harder to detect, even if the raw frequency of factual errors decreases somewhat — capability improvements don't inherently include built-in fact-verification.

30. What is a practical, production-level strategy combining multiple techniques to minimize hallucination risk in an AI system?
Combine RAG for grounding, strict prompting instructing the model to stay within provided context and express uncertainty, automated faithfulness/NLI checks on outputs before serving them, human review for high-stakes cases, and continuous monitoring/logging to catch and analyze hallucination patterns over time.

1️⃣4️⃣ QUERY OPTIMIZATION (30 Qs)

1. What is query optimization, and why does it matter for ML-backed applications?
The process of choosing the most efficient way to execute a database query (which indexes to use, join order, etc.) — critical for ML applications making frequent feature lookups or serving real-time predictions where slow queries directly hurt latency.

2. What is a query execution plan, and how is it inspected?
A step-by-step breakdown of how the database engine intends to execute a query (which indexes it will use, join strategies, scan types) — inspected using EXPLAIN (or EXPLAIN ANALYZE for actual runtime stats) in most SQL databases.

3. What is the difference between a full table scan and an index scan?
Full table scan: reads every row in the table to find matches (slow for large tables). Index scan: uses an index structure to jump directly to relevant rows — much faster when a suitable index exists on the filtered/joined column.

4. Why might a database choose a full table scan even when an index exists?
If the query optimizer estimates that a large percentage of the table's rows will match the filter (low selectivity), a full scan can actually be more efficient than using an index (which involves extra lookups per matching row).

5. What is index selectivity, and why does it matter?
The ratio of unique values to total rows for an indexed column — high selectivity (many unique values, e.g., user ID) makes an index very effective; low selectivity (e.g., a boolean flag) often makes the index less useful for filtering.

6. What is a composite index, and how does column order affect its usefulness?
An index on multiple columns together. The order matters because the index can efficiently support queries filtering on a left-to-right prefix of the indexed columns (e.g., an index on (a, b) helps queries filtering on a alone or a AND b, but not b alone).

7. What is the N+1 query problem, and how is it fixed?
Fetching a list of records, then issuing a separate query per record for related data (e.g., 1 query for orders + N queries for each order's items) — fixed using JOINs, eager loading, or batch-fetching related data in a single query.

8. What is the difference between EXPLAIN and EXPLAIN ANALYZE?
EXPLAIN shows the planned execution strategy (estimated costs) without running the query. EXPLAIN ANALYZE actually executes the query and shows real timing/row counts alongside the plan — more accurate for diagnosing actual performance issues.

9. How does adding an index affect write performance, and why is this a trade-off?
Every INSERT/UPDATE/DELETE must also update all relevant indexes on the table, adding overhead — so while indexes speed up reads, over-indexing can meaningfully slow down write-heavy workloads.

10. What is query caching, and what are the risks of using it?
Storing the results of a query so repeated identical queries can be served instantly without re-executing — risk: serving stale data if the underlying data changes and the cache isn't properly invalidated.

11. What is the difference between a correlated and non-correlated subquery, and which is generally slower?
Non-correlated: subquery runs once independently. Correlated: subquery re-executes once per row of the outer query (referencing outer query columns) — correlated subqueries are generally much slower and can often be rewritten as JOINs for better performance.

12. Why are JOINs often more efficient than subqueries for the same logical operation?
Query optimizers can often better plan and optimize JOIN operations (choosing efficient join algorithms, using indexes on join keys) whereas subqueries, especially correlated ones, can force row-by-row re-evaluation that's harder for the optimizer to flatten/optimize.

13. What is denormalization, and when would you use it to optimize query performance?
Intentionally introducing redundancy (e.g., storing a computed/duplicated value) to avoid expensive joins/calculations at query time — useful for read-heavy analytical workloads or ML feature-serving where query speed outweighs storage/write-complexity concerns.

14. What is a covering index, and why is it especially fast?
An index that contains all the columns needed to satisfy a query, so the database can return results directly from the index without needing to access the actual table rows — significantly reduces I/O.

15. What is the impact of using SELECT * vs selecting specific columns on query performance?
SELECT * retrieves all columns (potentially unnecessary data, more I/O/network transfer, and can prevent using a covering index) — explicitly selecting only needed columns reduces data transfer and can enable more optimized execution plans.

16. What is query plan caching, and why can stale cached plans sometimes hurt performance?
Databases often cache execution plans for repeated queries (with different parameter values) to avoid re-planning overhead — but if data distribution changes significantly (e.g., table grows a lot), an old cached plan optimized for different data characteristics ("parameter sniffing" issue) may become suboptimal.

17. What is the difference between vertical and horizontal filtering in query optimization strategy?
Not standard formal terms, but generally: filtering as early as possible (pushing WHERE conditions down before expensive joins/aggregations) and selecting only necessary columns (reducing row width) — both reduce the amount of data processed at each stage of query execution.

18. Why should WHERE clause filters generally be applied before JOINs when possible?
Reducing the number of rows early (via filtering) before performing expensive join operations minimizes the amount of data the join needs to process — most modern query optimizers do this automatically ("predicate pushdown"), but understanding it helps you write queries that are easier to optimize.

19. What is a materialized view, and how does it help with query optimization for expensive aggregations?
Precomputes and stores the result of a query physically (unlike a regular view which recomputes each time) — dramatically speeds up repeated access to expensive aggregate/summary queries at the cost of needing periodic refresh to stay current.

20. What is partition pruning, and how does it speed up queries on partitioned tables?
When a table is partitioned (e.g., by date), the query optimizer can skip scanning irrelevant partitions entirely if the query's filter clearly excludes them (e.g., a query for "last 7 days" skips partitions for older months) — dramatically reduces the data scanned.

21. What is the difference between a hash join, nested loop join, and merge join, and when is each preferred?
Nested loop: good for small tables/highly selective joins. Hash join: builds a hash table on one side, efficient for larger unsorted datasets without useful indexes. Merge join: efficient when both inputs are already sorted on the join key — the optimizer picks based on table sizes, available indexes, and data characteristics.

22. How does query optimization differ for OLTP workloads vs OLAP/analytical workloads?
OLTP: optimized for many small, fast, indexed point-lookup/transactional queries. OLAP: optimized for complex aggregations/scans over large datasets, often benefiting more from columnar storage, partitioning, and materialized views rather than traditional row-based indexes.

23. What is the impact of data types on query performance (e.g., using VARCHAR vs INT for a frequently filtered column)?
Numeric types are generally faster to compare/index than string types; mismatched or overly large data types can also prevent efficient index usage or force implicit type conversions that block index utilization ("non-sargable" conditions).

24. What is a "sargable" query, and why does it matter for optimization?
A query condition written so the database CAN use an index to search efficiently (Search ARGument ABLE) — e.g., WHERE date_column >= '2024-01-01' is sargable, but WHERE YEAR(date_column) = 2024 is often not, since applying a function to the column prevents direct index lookup.

25. What is connection pooling's relationship to query performance at scale (even though it's not query optimization per se)?
While not optimizing individual queries, efficiently reusing database connections reduces the overhead of connection establishment per request, which matters significantly at high query volume/concurrency, complementing actual query-level optimizations.

26. How would you optimize a slow analytical query joining a large "predictions" log table with a "users" table?
Check the execution plan for full scans, ensure indexes exist on join/filter columns, consider partitioning the predictions table by date, potentially pre-aggregate/denormalize frequently needed user attributes into the predictions table, or use a materialized view for recurring reporting queries.

27. What is query batching, and how does it help reduce database load in ML feature-serving scenarios?
Combining multiple individual lookups (e.g., fetching features for many entity IDs) into a single batched query (e.g., using WHERE id IN (...)) instead of issuing many separate round-trip queries — significantly reduces network overhead and database load.

28. What is the impact of table statistics on query optimizer decisions, and why must they be kept up to date?
The optimizer relies on statistics (row counts, value distributions) to estimate the cost of different execution strategies — stale statistics (e.g., after bulk data loads) can lead to poor plan choices (like unnecessarily choosing a full scan over an available index), so databases need periodic statistics updates (e.g., ANALYZE).

29. What is the difference between optimizing a single slow query vs optimizing overall database schema design for query performance?
Query-level optimization: rewriting/indexing for a specific problematic query. Schema-level optimization: broader design choices (normalization level, partitioning strategy, data types) that influence the performance ceiling/floor for many queries across the system — schema design often has a bigger long-term impact than individual query tweaks.

30. How would you approach diagnosing and fixing a sudden query performance regression in a production ML feature pipeline?
Check recent changes (schema migrations, data volume growth, missing/stale statistics), use EXPLAIN ANALYZE to compare the actual vs expected execution plan, verify indexes weren't dropped/altered, and check for lock contention or resource constraints (CPU/memory/disk I/O) on the database server.

1️⃣5️⃣ CACHE (30 Qs)

1. What is caching, and why is it critical for ML-serving systems?
Storing frequently accessed data/results in fast-access memory (rather than recomputing or re-fetching from a slower source) — reduces latency and backend load for repeated identical requests, common in feature lookups and prediction serving.

2. What is the difference between a cache hit and a cache miss?
Cache hit: requested data is found in the cache and returned quickly. Cache miss: data isn't in the cache, requiring a fallback to the slower original source (database/computation), and typically populating the cache for next time.

3. What is cache eviction, and name common eviction policies.
The process of removing entries from a full cache to make room for new ones. Common policies: LRU (Least Recently Used), LFU (Least Frequently Used), FIFO (First In First Out), and TTL-based (time-based expiration).

4. What is TTL (Time To Live) in caching, and why is it important?
A configured duration after which a cached entry is considered stale/expired and removed or refreshed — important for balancing performance gains against the risk of serving outdated data.

5. What is cache invalidation, and why is it considered a hard problem ("one of the two hard things in computer science")?
Actively removing/updating a cached entry when the underlying data changes — hard because it requires reliably knowing exactly when/what to invalidate across potentially many cache layers/consumers without causing inconsistency or unnecessary cache misses.

6. What is the difference between write-through and write-back (write-behind) caching?
Write-through: writes go to both cache and the underlying data store simultaneously (safer, slightly slower writes). Write-back: writes go to the cache first and are asynchronously persisted to the underlying store later (faster writes, risk of data loss if the cache fails before persisting).

7. What is write-around caching?
Writes go directly to the underlying data store, bypassing the cache — the cache is only populated on subsequent reads (cache miss triggers load) — useful when written data isn't immediately re-read often, avoiding cache pollution.

8. What is cache-aside (lazy loading), and how does it work?
The application code checks the cache first; on a miss, it fetches from the database, then explicitly populates the cache for future requests — one of the most common caching patterns, giving the application direct control over caching logic.

9. What is the "thundering herd" problem in caching, and how is it mitigated?
When a popular cached item expires, many simultaneous requests all miss the cache at once and hit the backend/database simultaneously, potentially overwhelming it — mitigated via request coalescing (only one request repopulates the cache while others wait), staggered/jittered TTLs, or locking.

10. What is a distributed cache (e.g., Redis, Memcached), and why is it needed over local in-process caching at scale?
A cache shared across multiple application server instances (rather than each instance keeping its own separate local cache) — ensures consistency and higher effective hit rates across a horizontally scaled service, since all instances share the same cached data.

11. What is the difference between Redis and Memcached at a high level?
Memcached: simple, purely in-memory key-value store, multi-threaded, good for straightforward caching. Redis: supports richer data structures (lists, sets, sorted sets), persistence options, pub/sub, and more advanced features beyond simple caching.

12. What is cache stampede, and how does it differ slightly from thundering herd?
Often used interchangeably with thundering herd — specifically refers to the scenario where a cache expiration causes a sudden surge of identical, redundant backend requests; mitigated with similar techniques (locking, early refresh before expiry, jitter).

13. What is the role of caching in reducing latency for embedding-based retrieval in a RAG system?
Caching frequent/repeated query embeddings or even full retrieval results avoids redundant embedding computation and vector search for identical or very similar queries, directly reducing end-to-end RAG pipeline latency.

14. What is negative caching, and why is it useful?
Caching the fact that a particular lookup returned "no result" (rather than only caching successful results) — prevents repeatedly hitting the backend for requests that are known to consistently fail/return nothing (e.g., invalid IDs).

15. What is the difference between caching at the application layer vs the database layer (e.g., a query result cache)?
Application-layer caching: explicit caching logic in application code (e.g., Redis lookups before hitting the DB). Database-layer caching: the database engine itself caches query plans/results/buffer pages internally — both can coexist, targeting different parts of the request path.

16. What is a CDN's role as a caching layer, and why does it matter for globally distributed users of an ML application?
Caches static (and sometimes dynamic/cacheable) content at edge servers geographically close to users, reducing latency and origin server load for users far from the primary data center.

17. What is cache warming, and when would you use it?
Proactively populating a cache with expected frequently-accessed data before it's actually requested (rather than waiting for organic cache misses) — useful after a deployment/restart or ahead of a predictable traffic spike (e.g., a planned product launch).

18. What is the trade-off between cache size and hit rate?
Larger caches can hold more entries, generally increasing hit rate, but consume more memory/cost and can have diminishing returns beyond a certain point depending on the access pattern (how "hot" a small subset of data is relative to the whole).

19. What is the difference between LRU and LFU eviction, and when might LFU be preferred?
LRU: evicts the item not accessed for the longest time. LFU: evicts the item accessed the fewest total times. LFU can be preferred when access frequency (not recency) better predicts future usefulness — e.g., a rarely-but-consistently-used item shouldn't be evicted just because it wasn't accessed in the last few minutes.

20. What is cache coherence, and why does it matter in a distributed caching setup?
Ensuring all cache nodes/replicas reflect a consistent view of the data — important in distributed caches to avoid different application instances seeing different (stale vs fresh) versions of the same cached key.

21. How would you decide what to cache in an ML prediction-serving API?
Cache predictions for identical/frequent input requests (especially for deterministic models), cache expensive-to-compute features that don't change often, and avoid caching highly personalized or rapidly-changing data where staleness would cause meaningful incorrect behavior.

22. What is the risk of caching LLM/generative model outputs, and how would you mitigate it?
Risk: caching based on exact input match may miss many semantically similar queries that could still benefit from a cached response, and stale cached generations may become outdated if underlying knowledge/context changes — mitigated via semantic caching (checking embedding similarity, not just exact match) with appropriate TTLs.

23. What is semantic caching in the context of LLM-based applications?
Instead of caching only exact-match queries, it caches based on semantic similarity (using embeddings) — a new query sufficiently similar to a previously cached query/response can reuse the cached result, improving hit rates for paraphrased or slightly varied queries.

24. What is the difference between client-side caching and server-side caching?
Client-side: cache stored on the user's device/browser (e.g., HTTP cache headers), reducing repeated network requests entirely. Server-side: cache stored on backend infrastructure (Redis, CDN edge, application memory), reducing backend computation/database load even though the client still makes a network request.

25. What HTTP headers control browser/client-side caching behavior?
Cache-Control (e.g., max-age, no-cache, no-store), ETag (validator for conditional requests), and Expires — used to instruct clients/intermediary caches how long and under what conditions a response can be reused.

26. What is cache penetration, and how is it different from cache stampede?
Cache penetration: repeated queries for data that doesn't exist at all (neither in cache nor the underlying store), bypassing the cache entirely every time and hitting the backend unnecessarily. Stampede: concerns popular, existing data whose cache entry expires, causing a burst of simultaneous backend hits — different root causes needing different fixes (negative caching for penetration, locking/jitter for stampede).

27. What is the impact of a poorly chosen cache key strategy, and give an example mistake.
A cache key that's too broad can cause incorrect data to be served to different users/contexts (e.g., caching a personalized recommendation under a key that doesn't include user ID); a key that's too narrow/specific reduces cache hit rate by fragmenting otherwise-shareable cached results unnecessarily.

28. What is the difference between caching computed model features vs caching final model predictions?
Caching features: reusable across multiple models/versions, useful when features are expensive to compute but predictions change often (e.g., due to frequent model updates). Caching predictions: more direct latency savings but must be invalidated/recomputed whenever the model itself is updated, since a cached old prediction becomes stale after a new model deployment.

29. How would you monitor and evaluate whether your caching strategy is effective in production?
Track cache hit rate, cache latency vs backend/database latency, memory/eviction rates, and end-to-end request latency before/after caching — a low hit rate might indicate poor key design, too-short TTLs, or genuinely low request repetition in the workload.

30. What is a scenario where caching could actually hurt an ML system's correctness, and how would you prevent it?
Caching predictions for a personalization model without properly scoping the cache key by user/context could serve one user's cached result to another; prevented by ensuring cache keys fully capture all relevant input dimensions (user ID, session context, model version) that affect the correct output.
